# 公司发展 / 并购拓展公司速览

## 目的

为内部公司发展团队评估潜在收购标的创建目标评估画像。不同于 IB/M&A 画像（它为推介材料讲述战略故事），本文件是聚焦战略契合度的分析文档：标的的产品、客户、技术和运营与收购方有哪些重叠或互补。公司发展团队已经了解自己的公司；他们需要从“是否应该买、整合会是什么样”这个视角理解标的。

**默认页数：** 1–2 页。企业发展团队可以接受密度更高的画像；只要内容实质充分，第 2 页不会被视为问题。

## 查询计划

从以下查询开始。如结果不完整，拆分查询并继续追问。

**查询 1 — 标的画像：**
`"[公司] 业务描述 产品 服务 技术 平台 总部 成立时间 员工数 板块 行业"`
→ 页眉、业务与产品概览
→ **立即写入** `/tmp/tear-sheet/company-profile.txt`

**查询 2 — 财务数据：**
`"[公司] 年度利润表 收入 毛利 EBITDA 经营利润 净利润 capex 自由现金流 R&D 费用 总债务 现金及等价物 最近 4 个财年"`
→ 财务摘要（拉取 4 年；展示 3 年；最早一年仅用于计算同比增长。R&D 对企业发展尤其重要，因为他们需要理解标的对 IP 的投入）
→ **立即将原始数值写入** `/tmp/tear-sheet/financials.csv`

**查询 3 — 分部 + 客户：**
`"[公司] 按分部收入 业务单元 最近 2 个财年 关键客户 终端市场 客户集中度"`
→ 收入结构（需要 2 年数据用于同比增长）、客户分析
→ **立即将分部数据写入** `/tmp/tear-sheet/segments.csv`（如未返回分部数据则跳过）

**查询 4 — 业务关系 + 竞争格局：**
`"[公司] 关键客户 供应商 合作伙伴 竞争对手 业务关系 技术供应商"`
→ 战略契合度分析、生态图谱
→ **立即写入** `/tmp/tear-sheet/relationships.txt`

**查询 5 — 估值 + 同业：**
如果用户提供了具体可比公司：
`"[可比公司] 企业价值 EV/收入 EV/EBITDA 收入增长 EBITDA 利润率"`
否则：
使用竞争对手工具识别 3–5 家上市同业，然后为每家拉取 EV/收入（NTM）、EV/EBITDA（NTM）、收入增长率 % 和 EBITDA 利润率 %。
另查：`"[公司] 企业价值 市值 估值倍数"`
→ 估值背景
→ **立即将公司倍数写入** `/tmp/tear-sheet/valuation.csv`
→ **立即将同业数据写入** `/tmp/tear-sheet/peer-comps.csv`

**查询 6 — 所有权（视数据可得性）：**
`"[公司] 所有权结构 投资人 机构持股 内部人持股"`
→ 所有权快照（不单独建中间文件；如可得，纳入 `company-profile.txt`）

## 章节

以下按优先级排序。明确裁剪指导见下方“页面预算与裁剪顺序”。

### 1. 公司页眉

类似 IB/M&A，但增加“战略相关性”标签语。

| 字段 | 说明 |
|---|---|
| 公司名称 | 大号、加粗 |
| 股票代码和交易所 | 如为上市公司；私营公司省略 |
| 总部地点 | |
| 成立年份 / 员工数 | |
| 企业价值 | 上市公司用市值/企业价值；私营公司用最新估值 |
| 所有权 | 公众公司 / PE 持股 / 创始人主导 / 等 |
| **战略相关性** | 一句话：为什么该标的对收购方有吸引力（基于数据综合判断） |

“战略相关性” 是公司发展版本独有的内容。使用中性分析视角撰写，不要照搬标的营销语言。表达收购方能“获得什么”，而不是标的“是什么”。好例子：“在商品价格基准领域具有主导地位，拥有监管壁垒和 70%+ 毛利率，是轻资本、高壁垒的数据资产。”坏例子：“全球领先的金融数据和分析提供商。”前者告诉公司发展团队为什么有吸引力；后者像新闻稿。

### 2. 业务与产品概览

**不要粘贴 CIQ 公司摘要。** 用 4–6 句重写（一段，不要两段），聚焦产品和技术；该受众评估收购，不是评估投资：
- 核心产品/服务及其解决的问题
- 技术或平台架构（高层级）
- 关键差异化和竞争壁垒
- 客户分层 — 谁会购买、为什么购买
- 当前战略方向

用收购方视角写。读者正在思考：“这和我们已有业务如何契合？” 描述应便于识别重叠和互补。

### 3. 收入结构与客户画像

两个子章节：

**a) 按分部拆分收入**（如可得）：

| 分部 | 收入（$M） | 占总收入比例 | 同比增长 |
|---|---|---|---|

**b) 客户分析：**
在分部表下方（如无分部数据，则替代表格位置）写一段定性分析，覆盖：
- 客户集中度：前 5 大客户是否贡献 >30% 收入？（这是收购风险中的关键信号）
- 客户类型：大型企业 / 中小企业 / 消费者
- 合同结构：订阅 / 交易型 / 许可（如已知）
- 地域组合

客户集中度是这里最重要的信号；如果工具返回任何头部客户或收入集中度数据，必须突出展示。若数据稀疏，则根据业务描述和关系数据做合理推断。控制在 2–3 句；它是分部表的背景，不是独立分析。

### 4. 战略契合度分析

**这是企业发展公司速览的标志性章节。** 必须包含，不要跳过或过度压缩。它使用 S&P Capital IQ 的业务关系数据来映射重叠和互补。

按三个类别组织。**每个类别必须是 2–3 句分析推理，而不是公司名称清单。** 只列“客户：Microsoft、JPMorgan、Google”没有价值。应解释该重叠或互补对收购意味着什么。

**客户重叠：** 标的客户是否也从收购方（或收购方所在行业）购买？共享客户意味着交叉销售更容易，但也可能带来渠道冲突。点名共享关系并解释影响。

**技术 / 产品互补：** 标的是否填补了收购方产品组合缺口？其技术栈是什么样？技术供应商是谁？如果标的已经使用收购方技术，解释为什么这是强整合信号。

**竞争替代：** 标的是竞争对手吗？收购标的是否能从市场中移除一个竞争者？点名标的关键竞争对手，并解释收购后竞争格局如何变化。

本节需要综合判断：把关系数据和业务概览结合起来建立联系。如果用户已经说明收购方是谁，围绕该收购方定制；如果没有，则保持通用但仍然要有分析性。

**长度纪律：** 上述每个类别的 2–3 句目标是硬约束，不是建议。每个要点应先给结论，再用一个具体数据点支持。实际输出很容易膨胀到每条 5–7 句，这是溢出到第 3 页的主要原因。如果写到超过 3 句，把多余细节移到整合考虑事项。

### 5. 财务摘要（3 年）

类似 IB/M&A，但更强调 R&D 和资本效率。

| 指标（$M） | FY20XX | FY20XX | FY20XX |
|---|---|---|---|
| 收入 | | | |
| 收入增速 % | | | |
| 毛利率 % | | | |
| EBITDA | | | |
| EBITDA 利润率 % | | | |
| R&D 费用 | | | |
| R&D / 收入 | | | |
| Capex | | | |
| 自由现金流 | | | |
| FCF 转化率（FCF/EBITDA） | | | |

R&D 强度说明标的价值有多少来自 IP 而不是服务。FCF 转化率说明整合复杂度；高 capex 业务更难整合。如果 R&D 费用未单独披露，在该行写“未单独披露”，而不是“N/A”；这本身也有信息含量（意味着 R&D 可能嵌在 COGS 或 SG&A 中）。

**资本结构**（放在财务摘要下方的紧凑子表）：

| 指标 | 数值 |
|---|---|
| 总债务 | $XXM |
| 现金及等价物 | $XXM |
| 净债务 | $XXM |
| 净债务 / EBITDA | X.Xx |

从收购语境解释：在表格下方加入一句话解读杠杆（例如：“$X 的净债务对应 Y.Yx EBITDA 杠杆，对投资级收购方而言可管理，但在 LBO 情景下会加重杠杆。”）。使用已取得的资产负债表数据。

### 6. 估值背景

**上市公司必须包含本节。** 企业发展团队需要市场语境来框定潜在报价。如果工具返回估值倍数，本节必须出现。不要为了节省空间删除它；应先删除所有权快照（章节 7）。

这不是正式估值；企业发展团队会做自己的 DCF。本节提供市场语境。

**a) 交易倍数**（如为上市公司）：

**同业语境是必需项，不是可选项。** 如果用户提供了可比公司，把每家公司单独列为一列。如果未提供可比公司，使用竞争对手工具识别 3–5 家上市同业，然后为每家拉取 EV/收入（NTM）、EV/EBITDA（NTM）、收入增长率 % 和 EBITDA 利润率 %。

| 指标 | [公司] | [同业 1] | [同业 2] | [同业 3] | 同业中位数 |
|---|---|---|---|---|---|
| EV/收入（NTM） | | | | | |
| EV/EBITDA 倍数（NTM） | | | | | |
| 收入增速 % | | | | | |
| EBITDA 利润率 % | | | | | |

单独看一家公司倍数，对企业发展团队没有意义；他们需要相对语境来判断标的是相对便宜还是昂贵。这是目标画像中最低可行的估值语境。

如果工具无法返回同业倍数，则展示公司自身倍数，并在表格下方列出选定同业名称供读者参考。

**b) 先例交易（视数据可得性）：**
如果 M&A 工具返回该公司同业或同一子行业的近期交易，展示如下：

| 日期 | 标的 | 收购方 | EV（百万美元） | EV/收入 | EV/EBITDA |
|---|---|---|---|---|---|

作为语境表述：“[子行业]近期交易以 X–Yx 收入估值。”

如果工具无法取得先例交易数据，写明“数据源未提供先例交易数据”，不要静默省略。不要编造先例交易倍数。

对私营公司，跳过交易倍数。先例交易（如可得）仍然有用。

### 7. 所有权快照（视数据可得性；如工具未返回则省略）

如果工具返回所有权数据，纳入紧凑区块：创始人/家族控制比例、PE 发起人信息、机构持股集中度。所有权结构会直接影响交易复杂度，也与整合考虑有关。

**不要包含管理团队表。** 没有 S&P Global 工具返回高管数据；见数据完整性规则 10。来自训练数据的管理层姓名会过时。

### 8. 整合考虑事项

**必需章节，不要删除。** 这是企业发展公司速览的分析收束部分。基于上文所有内容综合得出 3–4 条实质性要点：
- **关键风险：** 客户集中度、关键人物依赖、技术债迹象
- **整合复杂度：** 地域（多国家 = 更难）、员工人数、产品数量
- **协同信号：** 共享客户、互补产品、重叠技术供应商
- **未决问题：** 企业发展团队在出价前需要尽调什么？聚焦具体、可执行的尽调事项，而不是开放式战略问题。好例子：监管审批时间和辖区、关键合同中的控制权变更条款、关键人物留任风险（尤其是创始人/CTO）、客户合同可转让性、IP 所有权结构、未决诉讼。坏例子：“X 的壁垒有多强？”或“长期市场机会有多大？” — 这些是分析师问题，不是尽调事项。

明确标记这些为分析观察，而不是数据来源中的事实。

## 页面预算与裁剪顺序

**目标：2 页。** 企业发展画像可以用两页呈现实质内容，但除非用户明确要求更长格式，否则不得溢出到第 3 页。若内容超过 2 页，按以下顺序裁剪（每项完全裁掉后再进入下一项）：

1. 所有权概况（章节 7）— 整体省略
2. 收入结构下方的客户分析文案（章节 3）— 压缩到最多 2 句
3. 估值语境文案（章节 6）— 保留同业可比表，删除表格下方解释段
4. 先例交易（章节 6b）— 保留“不可得”说明；如果空间极端紧张则删除
5. 资本结构文案 — 保留表格，删除表格下方解释段
6. 战略契合度分析（章节 4）— 每条压缩到最多 2–3 句（不要删除整个章节）

绝不要裁掉：业务与产品概览（2）、财务摘要（5 核心表）、整合考虑（8）。

## 格式说明

- **战略契合度分析是核心。** 应使用有辨识度的格式：
  - 字号提高到 9.5pt（size: 19）— 略大于标准正文。本节应看起来像页面上最重要的内容。
  - 使用全局样式配置中的标准缩进块状要点（360 DXA 左缩进）。
  - 不要使用左侧边框强调；它在 docx-js 中渲染不稳定。
- 财务摘要应突出 R&D 和 FCF 转化率。
- 对上市公司，包含同业可比公司的估值语境是必需项；不要在所有权概况之前裁掉。
- 对私营标的，画像会更依赖定性章节（业务概览、战略契合度、关系）；这是正常且仍然很有价值。
- 语气：分析和评估，而不是宣传。它不是推介，而是评估。
- **两页纪律：** 渲染前先在脑中估算页数。战略契合度（3 条长要点）+ 整合考虑事项（4 条要点）加起来可能就占满一页；如果是这样，先压缩战略契合度要点。
