# IB 材料检查器

从四个维度对演示文稿做全面 QC。逐页阅读，然后报告发现。

## 环境检查

此 skill 同时适用于 PowerPoint add-in 和聊天场景。开始前先判断所处环境：

- **Add-in**：从实时打开的材料中读取。
- **Chat**：从上传的 `.pptx` 文件中读取。

本流程只读取并报告，不直接编辑，因此两种环境的工作流相同。

## 工作流

### 读取材料

从每一页提取文本，并记录每行来自哪一页。每个发现都需要页码级归因，例如“$500M 出现在第 3 页和第 8 页，但第 15 页显示 $485M”。30 页材料很难只靠工作记忆可靠处理；把提取出的文本写入文件，让数字检查脚本处理。

脚本需要带 slide 标记的类 Markdown 输入。格式如下：

```
## Slide 1
[第 1 页文本内容]

## Slide 2
[第 2 页文本内容]
```

### 1. 数字一致性

对收集到的文本运行提取脚本：

```bash
python scripts/extract_numbers.py /tmp/deck_content.md --check
```

脚本会标准化单位（$500M、$500MM、$500,000,000 → 同一数字），给数值分类（收入、EBITDA、倍数、利润率），并在同一指标类别于不同页面出现冲突数值时标记。这一环节最可能抓到人工第五遍通读仍会漏掉的问题。

除脚本标记的问题外，还要核验：
- 计算是否正确（总数加总、百分比加总、增速是否匹配起止值）
- 单位写法是否一致。材料应在 $M 和 $MM 中选择一种，并始终使用
- 时间口径是否对齐。FY、LTM、季度口径要明确标注

### 2. 数据与叙事一致性

将论断映射到支撑它的数据。材料常在这里悄悄出错：有人改了第 7 页图表，却忘了更新第 4 页叙事。

- 趋势表述（“利润率下降”）→ 图表是否真的朝这个方向变化？
- 市场地位表述（“#1 player”）→ 收入和份额数据是否支持？
- 合理性 → 在 1000 亿美元市场中收入 2 亿美元，对应 0.2% 份额；这通常不能支持“#1”表述

### 3. 语言润色

IB 材料有固定语体。扫描所有破坏该语体的表达：口语化措辞（“pretty good”“a lot of”）、缩写口语、感叹号、没有数字支撑的模糊量词、同一概念术语不一致。

替换模式见 `references/ib-terminology.md`。

### 4. 视觉与格式 QC

对每页运行标准视觉核验。重点检查：图表缺少来源引用、坐标轴标签缺失、字体不一致、数字格式漂移（同一材料中混用 1,000 和 1K）、日期格式漂移、脚注和免责声明缺口。

视觉核验能发现文本抽取看不到的重叠、溢出和对比度问题。不要跳过。没有来源引用的图表，在文本 dump 中看起来和正确标注来源的图表一样。

## 输出

使用 `references/report-format.md` 的结构。按严重程度分类：

- **严重**：数字不一致、事实错误、数据与叙事冲突。这些会阻断客户交付。
- **重要**：语言问题、缺少来源、术语漂移。应修复。
- **轻微**：字号、间距、日期格式等润色项。

先列严重问题。如果没有严重问题，也要明确说明。“未发现数字不一致”是一项发现，不是什么都没有。
