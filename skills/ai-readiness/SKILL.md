# 投资组合 AI Readiness

## 工作流

### 步骤 1：连接投资组合数据

首先询问用户投资组合材料存放在哪里。不要假设；提供以下选项：

- **MCP servers**：如已连接，可使用数据室、SharePoint、Google Drive 或投后运营数据库
- **本地文件**：磁盘上包含季度材料、财务数据、董事会材料包的文件夹路径
- **文件上传**：直接把 PDF、PowerPoint 或 Excel 拖入对话

连接后，拉取整个投资组合或子集的季度更新、董事会材料和财务数据。对每家公司提取：行业、收入、按职能划分的员工数、提到的技术栈，以及已经在推进的 AI/自动化举措。

如果用户只提供单家公司，仍然执行扫描，但跳过跨投资组合排序。

如果材料中不明显，先询问：
- 每家公司剩余持有期（距离退出只剩 12 个月时，AI payback 的重要性会下降）
- 是否已有被投公司部署过有效方案

### 步骤 2：逐家公司扫描

对每家公司回答三个 gate questions。三个都是 yes → **Go**。任意一个 no → **Wait**，并说明解除 blocker 的条件。

1. **数据是否存在？** 他们能否在无需先做 6 个月数据项目的情况下，为 use case 提供干净输入，例如客户清单、发票流、合同库？
2. **是否有 owner？** 管理团队中是否有人会真正推动，而不是只有一个会“支持”的 sponsor？
3. **能否 30 天内 pilot？** 一个团队、一个 workflow、现成工具。如果答案以“首先我们需要……”开头，那就不是 quick win。

然后识别前 2-3 个杠杆点。在成本结构和运营中寻找以下模式：

**Back Office（通常最快 pilot）**
- 发票处理、AP/AR 匹配、费用分类
- 合同抽象：供应商协议、租赁、客户 MSAs
- 月结：reconciliations、flux commentary、lender reporting 初稿

**收入 / Front Office**
- RFP 和 proposal 初稿；如果收入以项目制为主，这是大杠杆
- 销售电话摘要和 CRM 清洁
- 客服工单分诊和首轮回复起草
- 配置型/复杂产品报价

**运营（取决于行业）**
- SOP 和质量文档生成
- 排班和调度（现场服务、物流）
- 代码生成和审阅（软件类 portcos）

对每个杠杆点，用一行记录：它替代什么、每周节省多少 FTE-hours（假设节省 30-50%，不要假设 100%）、是购买现成工具还是需要轻量构建。

### 步骤 3：跨投资组合排序

把所有公司的每个杠杆点汇总到一张清单中。按以下标准排序：

1. **金额影响**：年化 EBITDA 贡献（成本削减 + 收入提升，扣除工具成本）
2. **见效速度**：首次可衡量结果所需月数
3. **概率**：根据数据质量、变革管理风险、管理团队能力折扣

平局时优先考虑剩余持有期 <18 个月的机会；这些机会要么现在推进，要么就不做。

输出排序表：

| 排名 | 公司 | 机会 | 估算 EBITDA（美元） | 见效月数 | Gate | 第一步 |
|---|---|---|---|---|---|---|
| 1 | | | | | Go | |
| 2 | | | | | Go | |
| 3 | | | | | 等待 — [blocker] | |

### 步骤 4：寻找可复制打法

投资组合中最高杠杆的动作，是把一个成功打法复制到多家公司。扫描以下模式：

- **同一行业、同一职能**：两家医疗服务 portcos 都有人工 prior-auth？一次实现，两处部署。
- **同一工具、不同公司**：如果某家 portco 已有可运行的发票处理方案，标记所有 AP volume 超过 X 百万美元的其他 portcos 作为 fast follower。
- **共享供应商议价**：三家 portcos 都购买同一工具，就可以发起价格谈判。

列出每个可复制打法的领头公司（验证该打法）和跟随公司（复制该打法）。

### 步骤 5：输出

为 operating partner 生成一页材料，用于 portfolio review：

1. **投资组合前 5 项**：步骤 3 的排序表，包含负责人和 30 天第一步
2. **可复制打法**：2-3 个可一次覆盖多家公司的打法手册
3. **按公司列示推进 / 等待**：每家公司一行；对等待项说明解除条件
4. **我们不做什么**：纸面上看起来不错但未通过门槛的机会，避免运营合伙人每季度重复争论
5. **汇总 EBITDA 贡献**：全投资组合 AI 机会总额，拆分第 1 年快速见效机会与第 2-3 年规模化机会

## 重要说明

- **按金额排序，而不是按兴奋度排序。** 在一家 4,000 万美元收入公司节省 40 万美元的 AP 自动化，通常胜过炫目的客户侧 chatbot。
- **约束几乎总是数据，而不是模型。** 如果一家公司无法提供干净客户清单，AI 不是第一个项目，数据清理才是。要直接说明。
- **优先现成工具。** 对缺少工程深度的公司来说，自定义构建慢、贵且脆弱。优先选择可购买并部署的工具。
- **Ownership 才是真正 gate。** 没有内部 owner 的 quick win 会在 90 天内死亡。如果管理团队没人想推动，无论金额多大都标记为 Wait。
- **持有期决定紧迫性。** 距离退出还有 3 年的公司可以做基础数据项目。12 个月后就要退出的公司，需要能体现在 CIM LTM EBITDA 中的成果，否则跳过。
- **失败 pilot 是信号。** 如果管理层已经尝试过某件事但没有坚持下来，先弄清原因，再决定是否提出同样方案。
