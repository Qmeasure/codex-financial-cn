# DCF 模型构建器

## 概览

该技能按照投资银行标准，为股票估值创建机构级 DCF 模型。每次分析都会产出一个详细的 Excel 模型（敏感性分析放在 DCF 工作表底部）。

## 工具

- 默认使用用户提供的全部信息，以及可用于数据获取的 MCP 服务器。

## 关键约束 - 请先阅读

以下约束适用于整个 DCF 模型构建流程。开始前必须审阅：

**环境：Office JS 与 Python/openpyxl：**
- **如果在 Excel 内运行（Office 加载项 / Office JS 环境）：** 直接使用 Office JS，不要使用 Python/openpyxl。通过 `range.formulas = [["=D19*(1+$B$8)"]]` 写入公式。不需要单独重算步骤，Excel 会原生计算。用 `range.format.*` 设置样式。同样适用“公式优先于硬编码”规则：对派生单元格设置 `.formulas`，绝不要设置 `.values`。
- **如果生成独立的 .xlsx 文件（没有实时 Excel 会话）：** 按下文使用 Python/openpyxl，然后在交付前运行 `recalc.py`。
- 本技能其余部分使用 openpyxl 示例；在 Office JS 环境中应将其转换为 Office JS API 调用，但所有原则（公式字符串、单元格批注、章节检查点、敏感性表循环）完全相同。

**⚠️ Office JS 合并单元格陷阱：** 构建包含合并单元格的章节标题时，不要先调用 `.merge()` 再在合并区域上设置 `.values`。Office JS 仍会报告该区域的原始维度，并抛出 `InvalidArgument: The number of rows or columns in the input array doesn't match the size or dimensions of the range`。正确做法是先把值写到左上角单元格，再合并并设置整个区域格式：

```js
// 错误 — 会抛出 InvalidArgument：
const hdr = ws.getRange("A7:H7");
hdr.merge();
hdr.values = [["市场数据与关键输入"]];  // 1×1 数组对 1×8 区域 → 失败

// 正确 — 先把值写入单个单元格，再合并并设置区域格式：
ws.getRange("A7").values = [["市场数据与关键输入"]];
const hdr = ws.getRange("A7:H7");
hdr.merge();
hdr.format.fill.color = "#1F4E79";
hdr.format.font.bold = true;
hdr.format.font.color = "#FFFFFF";
```

这适用于 DCF 中的每一个合并章节标题（市场数据、情景模块、现金流预测、终值、估值摘要、敏感性表）。

**公式优先于硬编码（不可协商）：**
- 每一个预测、利润率、折现因子、现值和敏感性单元格都必须是动态 Excel 公式；绝不能把 Python 计算出的值作为数字写入。
- 使用 openpyxl 时，`ws["D20"] = "=D19*(1+$B$8)"` 是正确的；`ws["D20"] = calculated_revenue` 是错误的。
- 只允许硬编码以下数字：(1) 原始历史输入，(2) 假设驱动项（增长率、WACC 输入、终值增长率 g），(3) 当前市场数据（股价、债务余额）。
- 如果发现自己正在 Python 中计算某个结果并写入模型，立即停止。用户修改假设时，模型必须能够联动变化。

**与用户逐步核验（不要端到端一次性构建）：**
- 数据获取后 → 向用户展示原始输入模块（收入、利润率、股份数、净债务），确认后再做预测。
- 收入预测后 → 展示预测收入和增长率，确认后再构建利润率模块。
- FCF 构建后 → 展示完整 FCF 明细，确认逻辑后再计算 WACC。
- WACC 计算后 → 展示计算过程和输入，确认后再折现。
- 终值 + PV 完成后 → 展示权益桥（EV → 权益价值 → 每股价值），确认后再做敏感性表。
- 在每个阶段捕捉错误；如果在敏感性表完成后才发现利润率假设错误，就意味着下游全部需要重建。

**敏感性表：**
- **行和列必须使用奇数个**（标准为 5×5，有时为 7×7），这样才能保证存在真正的中心单元格。
- **中心单元格 = 基准情形。** 轴值必须构造为中间行表头和中间列表头恰好等于模型实际假设。例如基准 WACC = 9.0%，中间行就是 9.0%；终值增长率 = 3.0%，中间列就是 3.0%。因此中心单元格输出必须等于模型实际隐含股价，这是表格构建正确性的合理性检查。
- **高亮中心单元格**，使用中蓝色填充（`#BDD7EE`）+ 加粗字体，让基准情形一眼可见。
- 填满所有单元格（通常 3 张表 × 25 个单元格 = 75 个），且每个单元格都用完整 DCF 重算公式。
- 使用 openpyxl 循环（或 Office JS 循环）以编程方式写入公式。
- 不得使用占位文本，不得使用线性近似，不得要求手工步骤。
- 每个单元格都必须针对该假设组合重算完整 DCF。

**单元格批注：**
- 每创建一个硬编码值，就同时添加单元格批注。
- 格式："来源：[系统/文档]，[日期]，[引用]，[如适用填写 URL]"
- 每个蓝色输入单元格都必须在进入下一章节前已有批注。
- 不要拖到最后再补，也不要写 "TODO: add 来源"。

**模型布局规划：**
- 写任何公式之前，先定义所有章节的行号位置。
- 先写所有标题和标签。
- 再写所有章节分隔行和空白行。
- 然后用已锁定的行号位置写公式。
- 公式创建后立即测试。

**公式重算：**
- 交付前运行 `python recalc.py model.xlsx 30`。
- 修复所有错误，直到状态为 "success"。
- 公式错误必须为零（#REF!、#DIV/0!、#VALUE! 等）。

**情景模块：**
- 为悲观/基准/乐观情形创建独立模块。
- 在每个模块中，将假设按预测年份横向展示。
- 使用 IF 公式：`=IF($B$6=1,[悲观单元格],IF($B$6=2,[基准单元格],[乐观单元格]))`
- 核验公式引用的是正确的情景模块单元格。

## DCF 流程工作流

### 步骤 1：数据获取与校验

从 MCP 服务器、用户提供的数据和网页获取数据。

**数据来源优先级：**
1. **MCP 服务器**（如已配置）- 来自 Daloopa 等提供方的结构化财务数据。
2. **用户提供的数据** - 来自用户研究材料的历史财务数据。
3. **网页搜索/抓取** - 在需要时获取当前价格、beta、债务和现金。

**校验清单：**
- 核验净债务与净现金（估值中的关键项）。
- 确认摊薄流通股数（检查近期回购/增发）。
- 验证历史利润率是否与商业模式一致。
- 将收入增长率与行业基准交叉检查。
- 核验税率是否合理（通常 21-28%）。

### 步骤 2：历史分析（3-5 年）

分析并记录：
- **收入增长趋势**：计算 CAGR，识别驱动因素。
- **利润率变化**：跟踪毛利率、EBIT 利润率、FCF 利润率。
- **资本密集度**：D&A 和 CapEx 占收入比例。
- **营运资本效率**：NWC 变动占收入增长比例。
- **回报指标**：ROIC、ROE 趋势。

创建摘要表，展示：
```
历史指标（LTM）:
收入: $X million
收入增长率: X% CAGR
毛利率：X%
EBIT 利润率：X%
D&A 占收入比例: X%
CapEx % of revenue: X%
FCF 利润率：X%
```

### 步骤 3：构建收入预测

**方法：**
1. 从最新实际收入开始（LTM 或最近财年）。
2. 对每个预测年度应用增长率。
3. 同时展示金额和计算出的增长率。

**增长率框架：**
- 第 1-2 年：较高增长，反映近期可见度。
- 第 3-4 年：逐步向行业平均水平收敛。
- 第 5 年及以后：接近终值增长率。

**公式结构：**
- 收入(Year N) = 收入(Year N-1) × (1 + Growth Rate)
- Growth %(Year N) = 收入(Year N) / 收入(Year N-1) - 1

**三情景方法：**
```
悲观情形：保守增长（例如 8-12%）
基准情形：最可能情景（例如 12-16%）
乐观情形：乐观增长（例如 16-20%）
```

### 步骤 4：经营费用建模

**固定/可变成本分析：**

经营费用应反映现实的经营杠杆：
- **Sales & Marketing**：通常为收入的 15-40%，取决于商业模式。
- **Research & Development**：科技公司通常为 10-30%。
- **General & Administrative**：通常为收入的 8-15%，公司规模扩大时体现杠杆。

**关键原则：**
- 所有百分比都基于收入，而不是毛利。
- 建模经营杠杆：随着收入扩大，占比应下降。
- S&M、R&D、G&A 保持单独行项目。
- 计算 EBIT = 毛利 - 经营费用合计。

**利润率扩张框架：**
```
Current State → Target State (Year 5)
毛利率: X% → Y%（基于规模、效率说明理由）
EBIT Margin: X% → Y%（收入增长 + 费用杠杆的结果）
```

### 步骤 5：自由现金流计算

**按正确顺序构建 FCF：**

```
EBIT
(-) 税项（EBIT × 税率）
= NOPAT（税后净营业利润）
(+) D&A（非现金费用，占收入比例）
(-) CapEx（占收入比例，通常 4-8%）
(-) Δ NWC（营运资本变化）
= 无杠杆自由现金流
```

**营运资本建模：**
- 按收入变动（delta revenue）的百分比计算。
- 典型区间：收入变动的 -2% 至 +2%。
- 负数 = 现金来源（营运资本释放）。
- 正数 = 现金使用（营运资本增加）。

**维护性 CapEx 与增长性 CapEx：**
- 维护性 CapEx：维持当前经营（约收入的 2-3%）。
- 增长性 CapEx：支持扩张（额外占收入 2-5%）。
- 总 CapEx 应与公司增长战略一致。

### 步骤 6：资本成本（WACC）研究

**股权成本的 CAPM 方法：**

```
股权成本 = 无风险利率 + Beta × 股权风险溢价

其中：
- 无风险利率 = 当前 10 年期国债收益率
- Beta = 股票相对市场指数的 5 年月度 beta
- 股权风险溢价 = 5.0-6.0%（市场标准）
```

**债务成本计算：**

```
税后债务成本 = 税前债务成本 × (1 - 税率)

通过以下信息确定税前债务成本：
- 信用评级（如有）
- 公司债券当前收益率
- 财务报表中的利息费用 / 总债务
```

**资本结构权重：**

```
市值 = 当前股价 × 稀释后股数
净债务 = 总债务 - 现金及等价物
企业价值 = 市值 + 净债务

股权权重 = 市值 / 企业价值
债务权重 = 净债务 / 企业价值

WACC =（股权成本 × 股权权重）+（税后债务成本 × 债务权重）
```

**特殊情形：**
- **净现金头寸**：如果现金 > 债务，则 Net Debt 为负数。
  - Debt Weight 可能为负。
  - WACC 计算应相应调整。
- **无债务**：WACC = 股权成本。

**典型 WACC 区间：**
- 大盘、稳定公司：7-9%。
- 成长型公司：9-12%。
- 高成长/高风险公司：12-15%。

### 步骤 7：折现率应用（5-10 年预测）

**年中惯例：**
- 假设现金流发生在年中。
- 折现期：0.5、1.5、2.5、3.5、4.5 等。
- 折现因子 = 1 / (1 + WACC)^期间。

**现值计算：**
```
对每个预测年份：
FCF 现值 = 无杠杆 FCF × 折现因子

示例（第 1 年）：
FCF = $1,000
WACC = 10%
期间 = 0.5
折现因子 = 1 / (1.10)^0.5 = 0.9535
PV = $1,000 × 0.9535 = $954
```

**预测期选择：**
- **5 年**：大多数分析的标准期限。
- **7-10 年**：具有更长增长跑道的高成长公司。
- **3 年**：成熟、稳定业务。

### 步骤 8：终值计算

**永续增长法（优先）：**

```
终值 FCF = 最后一年 FCF ×（1 + 终值增长率）
终值 = 终值 FCF /（WACC - 终值增长率）

关键约束：终值增长率 < WACC（否则价值趋于无穷）
```

**终值增长率选择：**
- 保守：2.0-2.5%（GDP 增长率）。
- 中性：2.5-3.5%。
- 激进：3.5-5.0%（仅适用于市场领导者）。

**不要超过**：无风险利率或长期 GDP 增长率。

**退出倍数法（替代）：**
```
终值 = 最后一年 EBITDA × 退出倍数

退出倍数来源：
- 行业可比公司交易倍数
- 先例交易倍数
- 典型区间：8-15x EBITDA
```

**终值现值：**
```
终值现值 = 终值 / (1 + WACC)^最终期间

最终期间需要反映时点：
5 年模型使用年中惯例时，期间 = 4.5
```

**终值合理性检查：**
- 应占企业价值的 50-70%。
- 如果 >75%，模型可能过度依赖终值假设。
- 如果 <40%，检查终值假设是否过于保守。

### 步骤 9：企业价值到权益价值桥

**估值摘要结构：**

```
(+) 预测期 FCF 现值合计 = $X million
(+) 终值现值 = $Y million
= 企业价值 = $Z 百万

(-) 净债务 [若为负则为 + 净现金] = $A million
= 股权价值 = $B 百万

÷ 稀释后股数 = C 百万股
= 隐含每股价格 = $XX.XX

当前股价 = $YY.YY
隐含回报 =（隐含价格 / 当前价格）- 1 = XX%
```

**关键调整项：**
- **净债务 = 总债务 - 现金及等价物**
  - 如为正：从 EV 中扣除（降低权益价值）。
  - 如为负（净现金）：加回 EV（提高权益价值）。
- **使用摊薄股数**：包含期权、RSU、可转债等潜在稀释证券。
- **其他调整项**（如适用）：
  - 少数股东权益。
  - 养老金负债。
  - 经营租赁义务。

**估值输出格式：**
```csv
估值组成部分,金额 ($M)
预测期 FCF 现值,X.X
终值现值,Y.Y
企业价值,Z.Z
(-) 净债务,A.A
股权价值,B.B
,,
流通股数 (M),C.C
隐含每股价格,$XX.XX
当前股价,$YY.YY
隐含上涨/(下跌)空间,+XX%
```

### 步骤 10：敏感性分析

在 DCF 工作表底部构建**三张敏感性表**，展示不同假设变化下的估值变化：

1. **WACC 与终值增长率** - 展示企业价值对折现率和永续增长率的敏感性。
2. **收入增长与 EBIT 利润率** - 展示收入增长和经营杠杆的影响。
3. **Beta 与无风险利率** - 展示股权成本组成项的敏感性。

**实现方式**：这些是简单的二维网格（不是 Excel 的“数据表”功能），每个单元格都写入公式。每个单元格都必须包含针对具体假设组合的完整 DCF 重算公式。关于如何用 openpyxl 以编程方式填充全部 75 个单元格，详见关键约束章节。

### 情景模块选择模式 - 遵循此方法

**每个情景的假设应组织在独立模块中：**

**关键结构 - 每个章节标题下三行：**

```csv
悲观情形假设（章节标题，跨列合并单元格）
假设,FY1,FY2,FY3,FY4,FY5
收入增长 (%),12%,10%,9%,8%,7%
EBIT 利润率 (%),45%,44%,43%,42%,41%

基准情形假设（章节标题，跨列合并单元格）
假设,FY1,FY2,FY3,FY4,FY5
收入增长 (%),16%,14%,12%,10%,9%
EBIT 利润率 (%),48%,49%,50%,51%,52%

乐观情形假设（章节标题，跨列合并单元格）
假设,FY1,FY2,FY3,FY4,FY5
收入增长 (%),20%,18%,15%,13%,11%
EBIT 利润率 (%),50%,51%,52%,53%,54%
```

**每个情景模块都必须有列表头行**，在章节标题下方立即展示预测年份（FY2025E、FY2026E 等）。没有这一行，用户无法判断每个假设值对应哪一年。

**如何引用假设 - 创建汇总列：**
1. 情景选择单元格（例如 B6）包含 1=悲观、2=基准或 3=乐观。
2. 创建一个汇总列，用 INDEX 或 OFFSET 公式从正确的情景模块拉取数据。
3. 预测公式引用汇总列（引用清晰）。
4. 每个情景模块都包含跨预测年份的完整 DCF 假设。

**推荐汇总列模式（使用 INDEX）：**
`=INDEX(B10:D10, 1, $B$6)`

**不要这样做 - 在各处散落 IF 语句：**
`=IF($B$6=1,[悲观模块单元格],IF($B$6=2,[基准模块单元格],[乐观模块单元格]))`

汇总列方法会集中逻辑，让模型更容易审计。

### 正确的收入预测模式

**先创建包含 INDEX 公式的汇总列，再在预测中引用它：**

**步骤 1 - FY1 增长率汇总列：**
`=INDEX([悲观 FY1 增长]:[乐观 FY1 增长], 1, $B$6)`

**步骤 2 - 收入预测引用汇总列：**
`第 1 年收入：=D29*(1+$E$10)`

其中：
- D29 = 前一年收入。
- $E$10 = FY1 增长率的汇总列单元格（包含 INDEX 公式）。
- $B$6 = 情景选择器（1=悲观、2=基准、3=乐观）。

**这种方法比在每个预测公式中嵌入 IF 语句更清晰**，也更容易审计当前使用了哪些情景假设。

### 正确的 FCF 公式模式

**使用包含 INDEX 公式的汇总列，再在 FCF 计算中引用它们：**

**汇总列方法：**
```csv
项目,公式,引用
D&A,=E29*$E$21,$E$21 = D&A % 汇总列
CapEx,=E29*$E$22,$E$22 = CapEx % 汇总列
Δ NWC,=(E29-D29)*$E$23,$E$23 = NWC % 汇总列
无杠杆 FCF,=E57+E58-E60-E62,E57=NOPAT E58=D&A E60=CapEx E62=Δ NWC
```

**每个汇总列单元格都包含一个 INDEX 公式**，根据情景选择器从对应情景模块拉取数据。这样可以保持预测公式清晰且可审计。

写公式之前，确认情景模块的行位置，并设置好汇总列。

### 正确的单元格批注格式

**每个硬编码值都需要以下格式：**

"来源：[系统/文档]，[日期]，[引用]，[URL，如适用]"

**示例：**
```csv
项目,来源批注
股价,来源：市场数据脚本 2025-10-12 收盘价
流通股数,来源：2024 财年 10-K 第 45 页附注 12
历史收入,来源：2024 财年 10-K 第 32 页合并报表
Beta,来源：市场数据脚本 2025-10-12 五年月度 beta
一致预期,来源：管理层指引 2024 年第 3 季度业绩会
```

### 正确的假设表结构

**关键：每个情景模块需要三个结构元素：**

1. **章节标题行**（合并单元格）：例如“悲观情形假设”。
2. **列表头行**，展示年份；这是必需项，不得跳过。
3. **数据行**，包含假设值。

**结构：**
```csv
悲观情形假设（章节标题 - 合并 A:G 列）
假设,FY1,FY2,FY3,FY4,FY5
收入增长 (%),X%,X%,X%,X%,X%
EBIT 利润率 (%),X%,X%,X%,X%,X%
终值增长,X%,,,,
WACC,X%,,,,

基准情形假设（章节标题 - 合并 A:G 列）
假设,FY1,FY2,FY3,FY4,FY5
收入增长 (%),X%,X%,X%,X%,X%
EBIT 利润率 (%),X%,X%,X%,X%,X%
终值增长,X%,,,,
WACC,X%,,,,

乐观情形假设（章节标题 - 合并 A:G 列）
假设,FY1,FY2,FY3,FY4,FY5
收入增长 (%),X%,X%,X%,X%,X%
EBIT 利润率 (%),X%,X%,X%,X%,X%
终值增长,X%,,,,
WACC,X%,,,,
```

**如果没有展示预测年份（FY2025E、FY2026E 等）的列表头行，用户无法判断每个假设值对应哪一年。这一行是强制要求。**

**然后创建汇总列**（通常放在右侧下一列），用 INDEX 公式根据情景选择器从选中情景模块拉取数据。你的预测公式引用的就是这条汇总列。

### 正确的行规划流程

**1. 先写所有标题和标签：**
```csv

1,[公司名称] DCF 模型
2,股票代码 | 日期 | 财年结束
4,情景选择器

```

**2. 写所有章节分隔行和空白行。**

**3. 然后用已锁定的行位置写公式。**

**4. 公式创建后立即测试。**

**把它想成施工：**
- 好做法：先浇筑地基，再建墙（结构稳定）。

**Excel 版本：**
- 好做法：先添加标题，再写公式（公式稳定）。
- 坏做法：先写公式，再添加标题（公式断裂）。

### 正确的敏感性表实现

**重要**：这些不是 Excel 的“数据 Table”功能。这些是简单网格，你会用 openpyxl 写入普通公式。是的，这意味着总共约 75 个公式（3 张表 × 每张 25 个单元格），但这很直接，也是必需项。

**以公式编程填充：**

每张敏感性表都必须完整填入公式，这些公式会针对每组假设重新计算隐含股价。**不要使用 Excel 的数据 Table 功能**（它需要手工介入，且无法通过 openpyxl 自动化）。

**实现方法 - 具体示例：**

**表结构 — 5×5 网格（奇数维度，基准情形居中）：**

如果模型基准 WACC = 9.0%，基准终值增长率 = 3.0%，则围绕这些值对称构建坐标轴：

```csv
WACC 与终值增长率,       2.0%,  2.5%,  3.0%,  3.5%,  4.0%
              8.0%,       [fml], [fml], [fml], [fml], [fml]
              8.5%,       [fml], [fml], [fml], [fml], [fml]
              9.0%,       [fml], [fml], [★  ], [fml], [fml]   ← 中间行 = 基准 WACC
              9.5%,       [fml], [fml], [fml], [fml], [fml]
             10.0%,       [fml], [fml], [fml], [fml], [fml]
                                   ↑
                          中间列 = 基准终值增长率 g
```

**★ = 中心单元格。** 它的公式输出必须等于模型实际隐含股价（来自估值摘要）。对该单元格应用中蓝色填充（`#BDD7EE`）和加粗字体，让基准情形有清晰视觉锚点。

**轴值规则：** `axis_values = [base - 2*step, base - step, base, base + step, base + 2*step]`，围绕基准对称，奇数数量保证存在中心。

**公式模式 - 单元格 B88（WACC=8.0%，终值增长率=2.0%）：**

B88 中的公式应使用以下输入重新计算隐含股价：
- 来自行表头的 WACC：`$A88`（8.0%）。
- 来自列表头的终值增长率：`B$87`（2.0%）。

**推荐方法：** 引用主 DCF 计算，但替换这些值。

**示例公式结构：**
`=([使用 $A88 作为折现率的 FCF 现值合计] + [使用 B$87 作为增长率、$A88 作为 WACC 的终值] - [净债务]) / [股数]`

**关键 - 5×5 网格中的每个单元格都要写公式（每张表 25 个单元格，总计 75 个单元格）。** 使用 openpyxl 在循环中以编程方式写入这些公式。不要跳过这一步，也不要留下占位文本。

**Python 实现模式：**
```python
# 填充敏感性表的伪代码
for row_idx, wacc_value in enumerate(wacc_range):
    for col_idx, term_growth_value in enumerate(term_growth_range):
        # 构建使用 wacc_value 和 term_growth_value 的公式
        formula = f"=<DCF recalc using {wacc_value} and {term_growth_value}>"
        ws.cell(row=start_row+row_idx, column=start_col+col_idx).value = formula
```

**用户打开模型时，敏感性表必须立即可用，不需要任何手工步骤。**

<common_mistakes>

本章节包含构建 DCF 模型时必须避免的全部错误模式。

### 错误：简化敏感性表近似或占位文本

**不要使用线性近似：**

```
// 错误 - 线性近似
B97: =B88*(1+(0.096-0.116))    // 假设关系是线性的

// 错误 - 除法捷径
B105: =B88/(1+(E48-0.07))      // 没有重算完整 DCF
```

**不要留下占位文本：**
```
// 错误 - 占位说明
"说明：使用 Excel 数据表功能（数据 → 模拟分析 → 数据表）填充敏感性表。"

// 错误 - 空单元格
[因为“这太复杂”而把单元格留空]
```

**不要混淆术语：**
- ❌ "敏感性表需要 Excel 的数据 Table 功能"（不对；那是我们不能使用的特定 Excel 工具）。
- ✅ "敏感性表是每个单元格都有公式的简单网格"（正确；这就是我们要构建的内容）。

**为什么这些捷径是错的：**
- 线性近似公式并没有真正重算 DCF，只是套用简单数学调整。
- 关系并非线性，因此结果会不准确。
- 占位文本需要用户手工介入。
- 交付时模型不能立即使用。
- 不专业，也未达到客户交付标准。
- 空单元格 = 交付物不完整。

**必须拒绝的常见自我合理化：**
"写 75+ 个公式感觉很复杂，所以我留一条说明让用户手工完成。"

**现实情况：** 使用 Python 和 openpyxl 循环时，写 75 个公式很直接。每个公式遵循同一模式，只是替换行/列值。这是交付物的必需部分。

**正确做法：** 为每个敏感性单元格填入公式，使其针对该假设组合重算完整 DCF。

### 错误：缺少单元格批注

**不要这样做：**
- 创建所有硬编码输入却不加批注。
- 认为“稍后再补”。
- 写 "TODO: add 来源"。
- 让蓝色输入没有文档说明。

**为什么这是错的：**
- 无法核验数据来源。
- 不符合 xlsx 技能要求。
- 无法审计。
- 后续修复会浪费时间。

**正确做法：** 每创建一个硬编码值，就同时添加单元格批注。

### 错误：公式行引用错位

**症状：**
FCF 章节引用了错误的假设行：
`D&A:  =E29*$E$34    // 应为 $E$21，但引用了错误行`
`CapEx: =E29*$E$41   // 应为 $E$22，但行已位移`

**发生原因：**
1. 先写公式。
2. 然后插入标题。
3. 所有行引用发生位移。
4. 公式现在指向错误单元格 → #REF! 错误。

**正确做法：** 先锁定行布局，再写公式。

### 错误：每个假设跨情景只用单行

**不要这样组织假设：**
```csv
假设,悲观,基准,乐观
FY1 收入增长,10%,13%,16%
FY2 收入增长,9%,12%,15%
```
这种纵向布局让人难以看到每个情景下跨年份的变化路径。

**为什么这是错的：**
- 难以看到每个情景内假设如何随年份演进。
- 更难比较完整预测期内的情景假设。
- 对审阅情景逻辑不够直观。

**正确做法：**
- 为每个情景（悲观、基准、乐观）创建独立模块。
- 在每个模块内，将假设按预测年份横向展示。
- 这样每个情景的假设更容易作为一个整体审阅。

### 错误：没有边框

**不要交付没有边框的模型：**
- 没有章节边界。
- 所有单元格混在一起。
- 难读且不专业。

**为什么这是错的：**
- 未达到客户交付标准。
- 难以导航。
- 看起来不成熟。

**正确做法：** 在所有主要章节周围添加边框。

### 错误：字体颜色错误或没有字体颜色区分

**不要这样做：**
- 所有文字都是黑色。
- 只使用填充色（没有字体颜色变化）。
- 混淆哪些单元格该是蓝色，哪些该是黑色。

**为什么这是错的：**
- 无法区分输入和公式。
- 审计变得不可能。
- 违反 xlsx 技能要求。

**正确做法：** 所有硬编码输入使用蓝色文字，所有公式使用黑色文字，工作表链接使用绿色文字。

### 错误：经营费用基于毛利

**不要这样做：**
`S&M: =E33*0.15    // E33 = 毛利 (WRONG)`

**为什么这是错的：**
- 经营费用随收入变化，而不是随毛利变化。
- 会产生不现实的利润率路径。
- 这不符合企业实际经营方式。

**正确做法：**
`S&M: =E29*0.15    // E29 = 收入 (CORRECT)`

### 前五大错误摘要

1. **公式行引用错位** → 写公式前先定义全部行位置。
2. **缺少单元格批注** → 创建单元格时同时加批注，不要最后补。
3. **简化敏感性表** → 所有单元格都填入完整 DCF 重算公式，不使用近似。
4. **情景模块引用错误** → 确保 IF 公式从正确的悲观/基准/乐观模块拉取数据。
5. **没有边框** → 添加专业章节边框，使模型达到客户交付标准。

此外，还要注意以下错误：

### WACC 计算错误
- 在资本结构中混用账面价值和市场价值。
- 错误使用 equity beta，而不是正确处理 asset/unlevered beta。
- 对债务成本错误应用税率。
- 无风险利率错误（必须使用当前 10 年期国债收益率）。
- 未针对净债务与净现金头寸进行调整。

### 增长假设缺陷
- 终值增长率 > WACC（会产生无限价值）。
- 预测增长率与历史表现不一致。
- 忽略行业增长约束。
- 收入增长未与单位经济模型一致。
- 利润率扩张缺少经营层面的理由。

### 终值错误
- 使用错误的增长方法（永续增长与退出倍数混用）。
- 终值 > 企业价值的 80%（提示过度依赖终值）。
- 终值利润率与稳态假设不一致。
- 终值折现期间错误。

### 现金流预测错误
- 经营费用基于毛利而不是收入。
- D&A/CapEx 百分比与商业模式不匹配。
- 营运资本变动计算不当。
- 年度之间税率不一致。
- NOPAT 计算错误。

**这些错误最常见。开始任何 DCF 构建前，请重新阅读本章节。**

## Excel 文件创建

**本技能对所有电子表格操作使用 `xlsx` 技能。** xlsx 技能提供：
- 标准化公式构建规则。
- 数字格式约定。
- 通过 `recalc.py` 脚本自动重算公式。
- 全面的错误检查和校验。

本技能创建的所有 Excel 文件都必须遵守 xlsx 技能要求，包括公式错误为零和正确重算。

## 质量评分标准

每个 DCF 模型都必须最大化以下目标：
1. **现实的收入和利润率假设**，基于历史表现。
2. **适当的资本成本计算**，使用规范 CAPM 方法。
3. **全面的敏感性分析**，展示估值区间。
4. **清晰的终值计算**，并有支持理由。
5. **专业模型结构**，支持情景分析。
6. **透明文档记录**，说明所有关键假设。

## 输入要求

### 最低必需输入
1. **公司标识符**：股票代码或公司名称。
2. **增长假设**：预测期收入增长率（或“使用一致预期”）。
3. **可选参数**：
   - 预测期（默认：5 年）。
   - 情景案例（悲观/基准/乐观的增长和利润率假设）。
   - 终值增长率（默认：2.5-3.0%）。
   - 如果不使用 CAPM，则提供具体 WACC 输入。

## Excel 模型结构

### 工作表架构

创建**两个工作表**：

1. **DCF** - 主估值模型，底部包含敏感性分析。
2. **WACC** - 资本成本计算。

**关键**：敏感性表放在 DCF 工作表底部（不是单独工作表）。这样可以把所有估值输出放在一起。

### 公式重算（强制）

创建或修改 Excel 模型后，使用 xlsx 技能中的 recalc.py 脚本**重算所有公式**：

```bash
python recalc.py [path_to_excel_file] [timeout_seconds]
```

示例：
```bash
python recalc.py AAPL_DCF_Model_2025-10-12.xlsx 30
```

该脚本会：
- 使用 LibreOffice 重算所有工作表中的所有公式。
- 扫描所有单元格中的 Excel 错误（#REF!、#DIV/0!、#VALUE!、#NAME?、#NULL!、#NUM!、#N/A）。
- 返回包含错误位置和数量的详细 JSON。

**预期输出格式：**
```json
{
  "status": "success",           // 或 "errors_found"
  "total_errors": 0,              // 错误总数
  "total_formulas": 42,           // 文件中的公式数量
  "error_summary": {}             // 仅在发现错误时出现
}
```

**如果发现错误**，输出会包含细节：
```json
{
  "status": "errors_found",
  "total_errors": 2,
  "total_formulas": 42,
  "error_summary": {
    "#REF!": {
      "count": 2,
      "locations": ["DCF!B25", "DCF!C25"]
    }
  }
}
```

交付模型前，必须修复所有错误，并反复运行 recalc.py，直到状态为 "success"。

### 格式标准

**重要**：公式构建规则和数字格式约定遵循 xlsx 技能。DCF 技能额外增加特定视觉呈现标准。

**配色方案 - 两层：**

**第 1 层：字体颜色（来自 xlsx 技能，强制）**
- **蓝色文字（RGB: 0,0,255）**：所有硬编码输入（股价、股份数、历史数据、假设）。
- **黑色文字（RGB: 0,0,0）**：所有公式和计算。
- **绿色文字（RGB: 0,128,0）**：指向其他工作表的链接（WACC 工作表引用）。

**第 2 层：填充色 — 专业蓝/灰色板（默认，除非用户另有指定）**
- **保持克制**：填充只使用蓝色和灰色。不要引入绿色、黄色、橙色或多种强调色。颜色过多的模型会显得业余。
- **默认填充色板：**
  - **章节标题**：深蓝色（RGB: 31,78,121 / `#1F4E79`）背景，白色加粗文字。
  - **子标题/列表头**：浅蓝色（RGB: 217,225,242 / `#D9E1F2`）背景，黑色加粗文字。
  - **输入单元格**：浅灰色（RGB: 242,242,242 / `#F2F2F2`）背景，蓝色字体；如果追求极简，也可以白底蓝字。
  - **计算单元格**：白底黑字。
  - **输出/摘要行**（每股价值、EV 等）：中蓝色（RGB: 189,215,238 / `#BDD7EE`）背景，黑色加粗字体。
- **仅此而已：3 种蓝色 + 1 种灰色 + 白色。** 抵制添加更多颜色的冲动。
- 用户提供的模板或明确配色偏好始终优先于这些默认值。

**两层如何协同：**
- 输入单元格：蓝色字体 + 浅灰填充 = “硬编码输入”。
- 公式单元格：黑色字体 + 白色背景 = “计算值”。
- 工作表链接：绿色字体 + 白色背景 = “来自其他工作表的引用”。
- 关键输出：黑色加粗字体 + 中蓝填充 = “这是答案”。

**字体颜色说明内容类型（输入/公式/链接）。填充颜色说明所处位置（标题/数据/输出）。**

**关键 WACC 公式：**

### 敏感性分析（DCF 工作表底部）

**术语提醒**：“敏感性表” = 带行表头、列表头和每个数据单元格公式的简单二维网格。不是 Excel 的“数据表”功能（数据 → 模拟分析 → 数据表）。你将使用 openpyxl 把普通 Excel 公式写入每个单元格。

**位置**：DCF 工作表第 87 行及以后（不是单独工作表）。

**三张敏感性表，纵向堆叠：**

1. **WACC 与终值增长率**（第 87-100 行）- 5x5 网格 = 25 个公式单元格。
2. **收入增长率与 EBIT 利润率**（第 102-115 行）- 5x5 网格 = 25 个公式单元格。
3. **Beta 与无风险利率**（第 117-130 行）- 5x5 网格 = 25 个公式单元格。

**需要写入的公式总数：75**（这是必需项，不是可选项）。

**关键**：所有敏感性表单元格都必须用 openpyxl 以编程方式填入公式。不要使用线性近似捷径。不要留下占位文本或关于手工步骤的说明。不要因为“太复杂”而合理化空单元格；使用 Python 循环生成公式。

**表格设置：**
1. 创建带行/列表头的表结构（待测试的假设值）。
2. 为每个数据单元格填入一个公式，该公式：
   - 使用行表头值（例如 WACC = 9.0%）。
   - 使用列表头值（例如终值增长率 = 3.0%）。
   - 用这些具体假设重算完整 DCF。
   - 返回该情景的隐含股价。
3. 交付时，所有单元格都必须包含可用公式。
4. 使用条件格式：更高数值用绿色色阶，更低数值用红色色阶。
5. 加粗基准情形单元格。
6. 表与表之间留 1-2 个空白行。

**不得需要手工介入**；用户打开文件时，敏感性表必须完整可用。

## 情景选择器实现

**三情景框架：**

### 熊市情景
- 保守收入增长（历史区间低端）。
- 利润率压缩或无扩张。
- 更高 WACC（风险溢价上升）。
- 更低终值增长率。
- 更高 CapEx 假设。

### 基准情景
- 一致预期或管理层指引下的收入增长。
- 基于经营杠杆的适度利润率扩张。
- 当前市场隐含 WACC。
- 与 GDP 对齐的终值增长率（2.5-3.0%）。
- 标准 CapEx 假设。

### 牛市情景
- 乐观收入增长（预测高端）。
- 显著利润率扩张。
- 更低 WACC（风险溢价下降）。
- 更高终值增长率（3.5-5.0%）。
- 更低 CapEx 密集度。

**公式实现：**

**不要在各处散落嵌套 IF 公式。** 应创建一个使用 INDEX 或 OFFSET 公式的汇总列，从适当的情景模块拉取数据。

**推荐模式（使用 INDEX）：**
`=INDEX(B10:D10, 1, $B$6)`，其中 `B10:D10` = 悲观/基准/乐观值，`1` = 行偏移，`$B$6` = 情景选择器单元格（1、2 或 3）。

**然后在所有预测中引用汇总列**：
`第 1 年收入：=D29*(1+$E$10)`，其中 $E$10 是第 1 年增长率的汇总列值。

这种方法集中情景逻辑，让模型更易审计和维护。

## 常见变体

### 高成长科技公司
- 更长预测期（7-10 年）。
- 更高初始增长率（20-30%）。
- 利润率随时间显著扩张。
- 更高 WACC（12-15%）。
- 建模单位经济（用户、ARPU 等）。

### 成熟/稳定公司
- 更短预测期（3-5 年）。
- 温和增长率（GDP +1-3%）。
- 稳定利润率。
- 更低 WACC（7-9%）。
- 关注现金生成和资本配置。

### 周期性公司
- 跨经济周期建模。
- 按周期中位水平标准化利润率。
- 考虑低谷和高峰情景。
- 根据周期性调整 beta。

### 多分部公司
- 为每个业务单元单独建立 DCF。
- 分部采用不同增长率和利润率。
- 使用分部加总估值。
- 考虑协同效应。
