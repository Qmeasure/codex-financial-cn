# 输出模式

当 skill 需要生成稳定、高质量输出时，使用这些模式。

## 模板模式

为输出格式提供模板。模板严格程度应匹配实际需求。

**对于严格要求（例如 API 响应或数据格式）：**

```markdown
## 报告结构

必须使用以下精确模板结构：

# [分析标题]

## 执行摘要
[用一段话概述关键发现]

## 关键发现
- 发现 1，附支持数据
- 发现 2，附支持数据
- 发现 3，附支持数据

## 建议
1. 具体、可执行的建议
2. 具体、可执行的建议
```

**对于灵活指引（需要适配具体情境时）：**

```markdown
## 报告结构

以下是合理的默认格式，但请根据判断调整：

# [分析标题]

## 执行摘要
[概览]

## 关键发现
[根据实际发现调整章节]

## 建议
[针对具体背景定制]

请根据具体分析类型调整章节。
```

## 示例模式

当输出质量依赖示例时，为 skill 提供输入/输出配对：

```markdown
## Commit message 格式

按照以下示例生成 commit message：

**示例 1：**
输入：新增基于 JWT token 的用户认证
输出：
```
feat(auth): 实现基于 JWT 的认证

新增登录端点和 token 校验中间件
```

**示例 2：**
输入：修复报告中日期显示错误的问题
输出：
```
fix(reports): 修正时区转换中的日期格式

在报告生成过程中统一使用 UTC 时间戳
```

遵循该风格：type(scope): 简短描述，然后提供详细解释。
```

示例比抽象描述更能帮助 Codex 理解期望的风格和细节层级。
