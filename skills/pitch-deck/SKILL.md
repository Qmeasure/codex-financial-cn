## ⚠️ 关键渲染限制

**LibreOffice 用于验证，但不能准确渲染 PowerPoint 文件。** 它可能破坏字体、渐变、形状位置、文字换行和部分表格格式。

**这意味着：** 在 LibreOffice 中通过视觉验证的幻灯片，在 Microsoft PowerPoint 中仍可能存在问题。验证循环能捕捉结构性问题（缺少内容、表格损坏、保留占位符格式），但**无法**捕捉字体替换、细微对齐偏移或渐变问题。

**强制动作：** 交付输出时始终包含以下说明：
> “本文件使用 LibreOffice 完成验证。由于可能存在渲染差异，请在分发前使用 Microsoft PowerPoint 审阅。”

## 模板填充工作流

复制并跟踪进度：

```
Pitch Deck 进度：
- [ ] 阶段 1：提取并验证来源数据
- [ ] 阶段 2：将内容映射到模板章节
- [ ] 阶段 3：用正确格式填充幻灯片
- [ ] 阶段 4：验证 → 修复 → 重复，直到干净
- [ ] 阶段 5：最终验证
```

### 阶段 1：数据提取
1. **创建原始模板备份**，在任何修改前复制为 `[filename]_backup.pptx`。直接编辑 XML 或意外错误可能损坏文件。
2. 识别全部来源材料（Excel、CSV、PDF 报告、Word 文档、数据库、网页来源）
3. 从每个来源提取相关数据点
4. 对照原始来源验证全部数字
5. 标准化单位和币种（将所有数字转换为模板中使用的主要单位/币种）
6. 记录需要校验的计算 → 公式见 [`calculation-standards.md`](reference/calculation-standards.md)

### 阶段 2：内容映射
1. **打开并视觉审阅模板** — 修改前理解模板结构、风格和既有内容
2. 分析模板结构 — 识别所有占位区域和内容框
3. 将来源数据映射到对应模板章节 → 映射指导见 [`slide-templates.md`](reference/slide-templates.md)
4. 识别占位说明框（任务创建者留下的彩色说明框）
5. 记录任何数据缺口或不匹配 → 解决方式见 [`slide-templates.md`](reference/slide-templates.md#handling-data-template-mismatches)

### 阶段 3：模板填充
1. **删除或重设占位框格式** — 彩色说明框说明要创建什么内容，而不是说明最终格式。删除它们，并在原位置创建格式正确的内容。见 [关键反模式](#关键反模式绝不要这样做)。
2. 用映射好的内容填充各章节（先关注内容）
3. **然后应用格式**，匹配模板风格 → 见 [`formatting-standards.md`](reference/formatting-standards.md)
4. 表格必须创建为真实表格对象（绝不要使用管道符/制表符分隔文本）→ 见 [`xml-reference.md`](reference/xml-reference.md#table-implementation)
5. 箭头/形状必须创建为 PowerPoint 对象 → 见 [`xml-reference.md`](reference/xml-reference.md#arrow-shapes)
6. 如任务文件提供公司 logo，则插入；如未提供，提示用户：“[未提供 LOGO - 请提供公司 logo]”

### 阶段 4：验证 → 修复 → 重复

**这是反馈循环。重复执行，直到全部检查通过或触发升级。**

```bash
# 转为图片进行视觉验证
soffice --headless --convert-to pdf presentation.pptx
pdftoppm -jpeg -r 150 presentation.pdf slide
```

**验证清单（逐张检查幻灯片图片）：**
- [ ] 文字在背景上是否清晰可读？
- [ ] 表格是否为真实对象（列对齐，不是管道符/制表符文本）？
- [ ] 图表/表格是否填满指定区域？
- [ ] 同一章节内要点格式是否一致？
- [ ] 同层级框的字号是否一致？
- [ ] 是否没有内容超出幻灯片边界？
- [ ] **是否没有保留占位符格式**（没有大块彩色框里直接塞数据）？
- [ ] **是否没有文字型“表格”**（没有 `|` 或 tab 分隔形成的假列）？
- [ ] **跨页一致性**：同一指标/数字在所有出现处是否一致？

**修复循环协议：**

| 循环 | 动作 |
|-------|--------|
| 1 | 修复所有已识别问题，重新验证 |
| 2 | 修复剩余问题，重新验证 |
| 3 | 如问题仍存在，记录剩余问题并升级给用户 |

**3 轮后如仍有问题：**
1. 列出每个未解决问题，包含页码和描述
2. 说明已尝试的修复
3. 交付文件并明确免责声明：“以下问题无法自动解决：[列表]。需要人工审阅。”

**不要**无限循环。有些问题（字体渲染、复杂形状对齐）可能需要在 PowerPoint 中人工处理。

### 阶段 5：最终验证

交付前完成 [最终质量检查清单](#最终质量检查清单)。

### 幻灯片层级（典型）

以下为典型范围；根据模板规格调整：

| 层级 | 示例 | 典型字号 | 风格 |
|-------|----------|--------------|-------|
| 标题 | 幻灯片标题 | 40–48pt | 加粗 |
| 副标题 | 市场定义、页面描述 | 18–22pt | 加粗 |
| 章节标题 | “关键预测”、“评论” | 14–16pt | 常规 |
| 区块标签 | “纳入分部”、“定义”侧栏 | 12–14pt | 常规 |

| 表头 | 列标题 | 10–12pt | 加粗 |

### 字体一致性匹配

处于**同一层级**的文本框必须使用相同字号：

| 同层级 | 必须与其匹配 |
|------------|-----------------|
| “纳入分部” | “排除分部” |
| “定义” | “范围说明” |
| 左栏要点 | 右栏要点 |
| 所有区块标签 | 彼此一致 |
| 所有章节标题 | 彼此一致 |

### 演示用四舍五入

以下为**典型惯例**；根据数值量级和模板风格调整：

| 数值类型 | 典型四舍五入 | 示例 |
|------------|------------------|---------|
| 大市场规模（$10bn+） | 到最接近的 $1bn | 18.5 → $19bn |
| 较小市场规模（<$10bn） | 到最接近的 $0.5bn 或 $0.1bn | 2.3 → $2.5bn |
| 区间 | 匹配来源精度 | 14.9–22.1 → $15–22bn |
| CAGR | 整数 % 或 0.5% | 16.4% → 16% 或 16.5% |
| 市场份额 | 到最接近的 5%，或匹配来源 | 21.4% → 20% |
| 倍数 | 1 位小数 | 9.69 → 9.7x |

**原则：** 四舍五入不应实质性改变数字。对较小数值使用更细精度。

### 文本密度规则

- 每个内容框最多 6–7 个要点
- 每个要点最多 2 行
- 括号示例：放在同一行或缩进到下一行
- 不要出现孤词（单个词落在新行）

### 对齐原则

**垂直堆叠的文本框**必须拥有相同：
- 左边距位置、要点缩进、文字起点、框宽

**水平相邻的文本框**必须拥有相同：
- 顶部位置、高度（尽可能）、内部 padding

### 多页一致性

同一数据出现在多页时：
- 使用相同数字、格式和术语
- 如果某页更新某指标，更新所有出现处
- 验证时交叉检查，捕捉不一致

## 强制要求

无论模板如何，下列要求不可协商：

| 要求 | 细节 |
|-------------|---------|
| **文字可读性** | 所有文字与背景必须有足够对比度。例如：深蓝、深绿、黑色背景上使用白色/浅色文字；白色、浅灰、浅黄背景上使用黑色/深色文字。 |
| **真实表格对象** | 表格数据必须是真实 table object，不得是制表符分隔文本。见 [`xml-reference.md`](reference/xml-reference.md#table-implementation)。 |
| **图表/表格尺寸正确** | 粘贴的视觉元素必须填满指定区域。见 [`formatting-standards.md`](reference/formatting-standards.md#chart-and-image-handling)。 |
| **格式一致** | 同一章节的 bullet 必须匹配（符号、字号、缩进）。同层级文本框必须使用相同字号。 |
| **内容边界** | 所有内容必须留在幻灯片边界内。脚注框宽度：16:9 约 32.5cm，4:3 约 24cm。 |
| **不保留占位格式** | 删除彩色说明框。主体内容按模板使用浅背景上的深色文字。 |

## 关键反模式：绝不要这样做

这些失败通常发生在把占位符格式误认为输出格式时。识别这些模式至关重要。

### 反模式 1：把数据填进占位说明框

**会发生什么：** 模板包含彩色说明框（黄色、橙色等），里面有指导文字。模型用真实数据替换指导文字，但保留了彩色框。

**为什么错：** 彩色框本身就是占位符。它告诉你这里放什么内容。最终输出应使用不同格式，通常是白色/浅色背景上的深色文字，或样式正确的形状。

**识别测试：** 如果填充后的幻灯片有大块彩色矩形并塞满数据文本，说明你复制了占位格式，而不是替换它。

**关键区别 — 两类“占位符”：**

| 类型 | 如何识别 | 怎么做 |
|------|-----------------|------------|
| **说明框** | 鲜艳颜色（黄色、橙色），包含“在此插入 X”之类指导文字，彩色背景上白色/浅色文字 | 删除整个形状，然后用生产格式创建新内容 |
| **版式占位符** | 属于幻灯片母版/版式，颜色中性并匹配模板主题，文字为“点击添加文本” | 保留形状，只替换文字内容 |

如不确定：检查同一模板的空白幻灯片上是否存在该形状。版式占位符会保留；说明框是普通形状。

### 反模式 2：文字型“表格”

**会发生什么：** 模型用分隔字符（`|`、tab、空格）创建看似表格的内容，而不是真实 table object。

**为什么错：** 这不是表格。列永远无法正确对齐，也无法一致格式化，看起来不专业。

**识别测试：** 如果你在输入 `|` 字符，或依靠空格/tab 创建列，你创建的是文本，不是表格。

**必须验证：** 创建任何表格后，确认它是真实 table object。验证方法见 [`xml-reference.md`](reference/xml-reference.md#critical-verify-tables-are-actual-table-objects)。

### 反模式 3：继承占位符对比度

**会发生什么：** 占位符使用彩色背景上的浅色文字（例如黄色上的白色）。模型填入数据但保留该配色，导致输出难以阅读。

**为什么错：** 占位符颜色故意醒目，用于提示“替换我”。生产幻灯片正文通常使用浅色背景上的深色文字。

**识别测试：** 如果填充后的主体内容（非页眉）在鲜艳彩色背景上使用浅色/白色文字，说明继承了占位符格式。

**正确做法：** 应用生产格式，主体内容通常为白色或浅色背景上的深色文字（#000000 或 #333333）。标题和强调区域可使用品牌色。

### 小结：占位符 vs. 生产输出

| 元素 | 占位符（输入） | 生产输出 |
|---------|---------------------|---------------------|
| 说明框 | 彩色背景、指导文字 | 删除或重新格式化 |
| 数据区域 | “[Insert data here]” 文本 | 使用干净格式的真实数据 |
| 表格 | 描述表格应包含什么 | 真实 table object，含行列 |
| 正文 | 彩色背景上的浅色文字 | 浅色背景上的深色文字 |

**占位符告诉你要创建什么，而不是最终如何格式化。**

## 错误处理

**如果 PDF/图片转换失败：**
1. 检查是否安装 LibreOffice：`which soffice`
2. 尝试替代命令：`libreoffice --headless --convert-to pdf presentation.pptx`
3. 如仍失败，手动在 PowerPoint/LibreOffice 中打开并导出

**如果来源数据不一致或冲突：**
1. **优先级顺序**：优先使用任务文件中明确提供的数据
2. 如使用其他来源（网页搜索、外部文件），向用户标记这一点
3. 明确记录任何差异
4. 添加脚注说明数据来源选择

**如果计算与来源预测不一致：**
1. 展示计算方法
2. 说明差异及可能原因（基准年不同、方法不同）
3. 如差异重大，同时呈现两个值
4. 标记给用户解决

## 表格结构指南

创建表格时（必须是真实 table object）：

**列对齐：**
- 文本列：左对齐（表头和内容）
- 数字列：右对齐或居中（表头与内容一致）

**表头行：**
- 文字加粗
- 阴影背景（模板品牌色）
- 使用白色或高对比文字

**一致预期/合计行：**
- 文字加粗
- 上方分隔线
- 区分背景阴影

**宽度：** 完全填满指定章节宽度。

XML 实现见 [`xml-reference.md`](reference/xml-reference.md#table-implementation)。

## 脚注格式

**格式：**
```
来源：[来源 1]（年份），[来源 2]（年份）。
注：（1）[第一条注释]；（2）[第二条注释]。
```

**示例：**
```
来源：Grand View Research（2024），Mordor Intelligence（2024），Markets and Markets（2023）。
注：（1）不包括硬件收入；（2）包括 B2B 和 B2C 分部。
```

幻灯片正文中的所有上标数字（¹、²、³）都必须有对应注释条目。

- [ ] 所有数字与原始来源文件一致
- [ ] 计算值已按公式验证（见 [`calculation-standards.md`](reference/calculation-standards.md)）

- [ ] 公司/竞争对手名称拼写正确

### 内容映射
- [ ] 每个模板章节都填入了合适数据
- [ ] 没有残留 `[bracket]` 占位文字
- [ ] 所有来源引用已写入脚注
- [ ] 脚注数字（¹²³）有对应注释条目

### 格式
- [ ] 文字在所有背景上均清晰可读（对比度足够）
- [ ] 表格是真实 table object（不是管道符/tab 分隔文本）
- [ ] 图表/表格填满指定区域（不是缩略图）
- [ ] 每个章节内要点格式一致
- [ ] 同层级文本框字号一致
- [ ] 没有内容超出幻灯片边界
- [ ] 没有保留占位框并在其中直接塞数据
- [ ] 最终输出中没有彩色说明框

### 模板合规
- [ ] 占位说明框已重新格式化或删除
- [ ] 格式匹配模板风格（颜色、字体）
