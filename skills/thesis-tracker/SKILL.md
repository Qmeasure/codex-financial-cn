## 中文版执行契约

- 默认使用中国大陆金融语境：A股优先，港股和美股兼容；如用户指定市场、币种、会计准则或模板，以用户输入为准。
- 数据来源必须遵守插件根目录 `../../DATA_SOURCES_CN.md`：官方披露、用户文件、已授权 MCP/数据库优先；免费源只作辅助；监管、会计、KYC、基金文件和月结判断缺少依据时不得下结论，只在数据源发现记录中列为未覆盖数据项。
- 所有产物必须遵守插件根目录 `../../CN_OUTPUT_FORMATTING.md`：中文字体栈、中文日期、币种/单位、图表标题、表格表头、来源脚注、风险提示和免责声明都要按中文机构材料处理。
- 用户模板和品牌规范优先，但不得突破中文可读性、来源脚注、币种/单位/日期/口径说明这些底线。
- 保留 DCF、LBO、WACC、EV/EBITDA、IRR、MOIC、NAV、KYC、AML、MCP、CLI 等专业缩写和代码标识。

# 投资论点跟踪

## 工作流

### 第 1 步：定义或加载论点

如果创建新论点：
- **公司**：名称和 ticker
- **方向**：多头或空头
- **论点陈述**：1-2 句核心论点（例如“做多 ACME：产品结构转向软件后，定价权 + 经营杠杆驱动利润率扩张”）
- **核心支柱**：3-5 个支持论据
- **关键风险**：3-5 个可能推翻论点的风险
- **催化剂**：可能验证或证伪论点的即将发生事件（业绩、产品发布、监管决定）
- **目标价 / 估值**：如果论点兑现，公司应值多少钱
- **止损触发条件**：什么情况会让你退出

如果更新现有论点，向用户询问新的数据点或进展。

### 第 2 步：更新日志

对每个新数据点或进展：

- **日期**：发生时间
- **数据点**：发生了什么变化（业绩超预期、管理层离职、竞争对手动作等）
- **论点影响**：增强、削弱还是中性影响某一支柱？
- **行动**：不变 / 加仓 / 减仓 / 退出
- **更新后确信度**：高 / 中 / 低

### 第 3 步：论点评分卡

维护持续更新的评分卡：

| 支柱 | 原始预期 | 当前状态 | 趋势 |
|------|----------|----------|------|
| 收入增长 >20% | 符合预期 | Q3 为 22% | 稳定 |
| 利润率扩张 | 落后 | 利润率同比持平 | 需关注 |
| 新产品发布 | 待验证 | 延迟至 Q2 | 观察 |

### 第 4 步：催化剂日历

跟踪即将发生的催化剂：

| 日期 | 事件 | 预期影响 | 备注 |
|------|------|----------|------|
| | | | |

### 第 5 步：输出

输出适用于以下场景的论点摘要：
- 晨会讨论
- 组合审阅
- 风险委员会展示

格式：简洁 Markdown 或 Word 文档，包含评分卡、近期更新和当前确信度。

## 重要说明

- 论点应可证伪；如果没有任何事情能推翻它，它就不是论点
- 像跟踪支持证据一样严格跟踪反证证据
- 至少每季度审阅一次论点，即使没有发生重大事件
- 如果用户管理多个持仓，可主动提出做完整组合论点审阅
- 以结构化格式保存论点数据，便于跨会话引用
