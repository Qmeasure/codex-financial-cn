## 给 Codex 的关键指令 - 请先阅读

### 环境：Office JS 与 Python

**如果在 Excel 内运行（Office 加载项 / Office JS 环境）：**
- 直接使用 Office JS（`Excel.run(async (context) => {...})`），不要使用 Python/openpyxl。
- 通过 `range.formulas = [["=B5*B6"]]` 写入公式；Office JS 公式会在实时工作簿中原生重算。
- 同样适用“公式优先于硬编码”规则：任何应为计算的内容都设置 `range.formulas`，绝不要设置 `range.values`。
- 使用 `range.format.font.color` / `range.format.fill.color` 实现蓝/黑/紫/绿约定。
- 不需要单独重算步骤，Excel 会原生处理计算。
- **合并单元格陷阱：** 不要先调用 `.merge()` 再在合并区域上设置 `.values`（会抛出 `InvalidArgument`，因为区域仍报告原始维度）。正确做法：只把值写到左上角单元格（`ws.getRange("A7").values = [["SOURCES & USES"]]`），然后合并并设置完整区域格式（`ws.getRange("A7:F7").merge(); ws.getRange("A7:F7").format.fill.color = "#1F4E79";`）。

**如果生成独立 .xlsx 文件（没有实时 Excel 会话）：**
- 按下文使用 Python/openpyxl。
- 写入公式字符串（`ws["D20"] = "=B5*B6"`），然后在交付前运行 `recalc.py`。

本技能其余部分使用 openpyxl 示例，但相同原则适用于 Office JS；只需要转换 API 调用。

### 核心原则
* **每项计算都必须是 Excel 公式** - 绝不要在 Python 中计算值并把结果硬编码到单元格。使用 openpyxl 时，写 `cell.value = "=B5*B6"`（公式字符串），不要写 `cell.value = 1250`（计算结果）。模型必须动态，输入变化时要自动更新。
* **使用模板结构** - 遵循 `examples/LBO_Model.xlsx` 或用户提供模板中的组织方式。不要发明自己的布局。
* **使用正确单元格引用** - 所有公式都应引用相应单元格。绝不要手输本应来自其他单元格的数字。
* **保持符号约定一致** - 遵循模板使用的符号约定（有些模板现金流出为负，有些为正）。全程保持一致。
* **逐章节工作，并在每一步与用户核验** - 完整完成一个章节，向用户展示已构建内容，运行该章节核验检查，并在进入下一章节前取得确认。不要端到端构完整个模型后才展示；后续章节依赖前面章节，如果在回报分析已经构建后才发现资金来源与用途错误，就会导致全局返工。

### 公式字体颜色约定
* **蓝色（0000FF）**：硬编码输入，即不引用其他单元格的手输数字。
* **黑色（000000）**：包含计算的公式，即任何使用运算符或函数的公式（`=B4*B5`、`=SUM()`、`=-MAX(0,B4)`）。
* **紫色（800080）**：链接到**同一标签页**单元格的直接引用，没有计算（`=B9`、`=B45`）。
* **绿色（008000）**：链接到**不同标签页**单元格的跨表引用（`=假设!B5`、`='经营模型'!C10`）。

### 填充色板 — 专业蓝色与灰色（默认，除非用户/模板另有指定）
* **保持极简**：单元格填充只使用蓝色和灰色。不要引入绿色、黄色、红色或多种强调色。专业 LBO 模型需要克制。
* **默认填充色板：**
  * **章节标题**（资金来源与用途、经营模型等）：深蓝 `#1F4E79`，白色加粗文字。
  * **列表头**（第 1 年、第 2 年等）：浅蓝 `#D9E1F2`，黑色加粗文字。
  * **输入单元格**：浅灰 `#F2F2F2`（或白底）；蓝色**字体**才是主要信号，填充色为辅助。
  * **公式/计算单元格**：白底，无填充。
  * **关键输出**（IRR、MOIC、Exit Equity）：中蓝 `#BDD7EE`，黑色加粗文字。
* **完整色板就是这些。** 3 种蓝色 + 1 种灰色 + 白色。如果模板使用自己的颜色，遵循模板。
* 说明：上面的蓝/黑/紫/绿**字体**颜色用于区分输入、公式和链接；这里的**填充**色板是另一层，两者共同发挥作用。

### 数字格式标准
* **货币**：`$#,##0;($#,##0);"-"` 或 `$#,##0.0`，取决于模板。
* **百分比**：`0.0%`（一位小数）。
* **倍数**：`0.0"x"`（一位小数）。
* **MOIC/详细比率**：`0.00"x"`（两位小数以保证精度）。
* **所有数字单元格**：右对齐。

## 模板分析阶段 - 必须先做

填充任何公式前，彻底检查模板：

1. **映射结构** - 识别每个章节的位置以及相互关系。记录哪些章节流入其他章节。

2. **理解时间线** - 哪些列代表哪些期间？是否有 "Closing" 或 "Pro Forma" 列？预测期从哪里开始？

3. **识别输入单元格与公式单元格** - 模板通常使用颜色编码、边框或底色表示哪些单元格需要输入，哪些是公式。尊重这些约定。

4. **仔细阅读既有标签** - 行标签会准确说明预期计算。不要假设；阅读模板要求。

5. **检查既有公式** - 有些模板已经部分填好。除非明确要求，否则不要覆盖可用公式。

6. **记录模板特定约定** - 符号约定、小计结构、章节组织方式、是否为不同组件设置独立标签页等。

## 填充公式 - 通用方法

对于每个需要公式的单元格，按以下层级处理：

### 步骤 1：检查模板
* 该单元格是否已有公式？如果有，验证其正确性后继续。
* 是否有批注或说明指明预期计算？
* 行/列标签是否已清楚说明计算方式？
* 相邻单元格是否展示了应遵循的模式？

### 步骤 2：检查用户指令
* 用户是否指定了特定计算方法？
* 是否有会影响此公式的已说明假设？
* 是否提到特殊要求？

### 步骤 3：应用标准实践
* 如果模板和用户都没有指定，使用标准 LBO 建模约定。
* 记录你所做的任何假设。
* 如果确实不确定，询问用户。

## 常见问题区域

以下计算模式经常在 LBO 模型中引发问题。遇到这些内容时要特别注意：

### 平衡章节
* 当两个章节必须相等（例如资金来源 = 资金用途）时，通常有一个项目是平衡项。
* 识别哪个项目是平衡项，并将其计算为差额。

### 税费计算
* 税费公式应只引用相关利润行和税率。
* 不应引用无关章节（例如债务明细表）。
* 考虑亏损是产生税盾，还是直接忽略。

### 利息与循环引用
* 如果利息计算引用了受现金流影响的余额，就可能产生循环。
* 使用**期初余额**（不是平均余额或期末余额）来打破循环引用。
* 模式：Interest → 现金流量表 → Paydown → Ending Balance；如果利息使用期末余额，就会形成循环。

### 债务偿还 / 现金清扫
* 当存在多层债务时，通常有偿还优先级。
* 现金清扫应遵守优先级 waterfall。
* 余额不能为负；应适当使用 MAX 或 MIN 函数。

### 回报计算（IRR/MOIC）
* 现金流符号必须正确：投资 = 负数，回收 = 正数。
* 如果使用 XIRR，需要对应日期。
* 如果使用 IRR，现金流应处于连续期间。
* MOIC = 总回收金额 / 总投资额。

### 敏感性表
* **使用奇数维度**（5×5 或 7×7），绝不要用 4×4 或 6×6。奇数维度保证真正存在中心单元格。
* **中心单元格 = 基准情形。** 围绕模型实际假设对称构造行轴和列轴值（例如基准 entry multiple = 10.0x，则轴 = `[8.0x, 9.0x, 10.0x, 11.0x, 12.0x]`）。中心单元格的 IRR/MOIC 必须等于模型实际 IRR/MOIC 输出，这证明表格联动正确。
* **高亮中心单元格**：中蓝色填充（`#BDD7EE`）+ 加粗字体，使基准情形具备视觉锚点。
* Excel 的 DATA TABLE 功能可能无法配合 openpyxl 使用；应改为写入引用行/列表头的显式公式。
* 每个单元格都应显示不同数值；如果全部相同，说明公式没有正确随输入变化。
* 使用混合引用（例如行输入用 `$A5`，列输入用 `B$4`）。

## 完成后运行的核验清单

### 运行公式校验
```bash
python recalc.py model.xlsx
```
必须返回成功且错误为零。

### 章节平衡
- [ ] 任何必须平衡的章节（资金来源/资金用途、资产/负债）都精确平衡。
- [ ] 平衡项作为平衡差额正确计算。
- [ ] 跨章节应匹配的金额保持一致。

### 收入/经营预测
- [ ] 收入/营业额根据驱动项或增长率正确构建。
- [ ] 所有成本和费用项目计算适当。
- [ ] 小计和合计加总正确。
- [ ] 利润率和比率合理。
- [ ] 与假设的链接正确。

### 资产负债表（如适用）
- [ ] Assets = Liabilities + Equity（必须平衡）。
- [ ] 所有项目链接到适当明细表或滚动表。
- [ ] 期初余额 = 上期期末余额。
- [ ] 包含检查行且显示为零。

### 现金流量表（如适用）
- [ ] 从正确利润数字开始。
- [ ] 非现金项目适当加回/扣除。
- [ ] 营运资本变动符号正确。
- [ ] Ending Cash = Beginning Cash + Net 现金流量表。
- [ ] 现金余额在各报表之间一致。

### 支持性明细表
- [ ] 滚动表平衡（Beginning + Changes = Ending）。
- [ ] 明细表正确链接到主报表。
- [ ] 计算项使用适当驱动项。
- [ ] 所有期间计算一致。

### 债务/融资明细表（如适用）
- [ ] 期初余额勾稽到 sources 或上一期。
- [ ] 利息按适当余额计算（通常为期初余额）。
- [ ] 偿债遵守现金可用性和优先级。
- [ ] 期末余额不能为负。
- [ ] 各债务层级合计正确。

### 回报/输出分析
- [ ] 退出/终值计算正确。
- [ ] 纳入所有相关调整项。
- [ ] 现金流符号正确（投资为负，回收为正）。
- [ ] IRR/MOIC 公式引用完整区间。
- [ ] 结果对该情景而言合理。

### 敏感性表（如适用）
- [ ] 网格维度为奇数（5×5 或 7×7），存在真正中心单元格。
- [ ] 行轴和列轴值围绕基准情形对称（`[base-2Δ, base-Δ, base, base+Δ, base+2Δ]`）。
- [ ] 中心单元格输出等于模型实际 IRR/MOIC，确认表格联动正确。
- [ ] 中心单元格已高亮（中蓝填充 `#BDD7EE`、加粗字体）。
- [ ] 行表头和列表头包含适当输入值。
- [ ] 每个数据单元格都包含公式（不是硬编码）。
- [ ] 每个数据单元格都显示不同数值。
- [ ] 数值按预期方向变化（更高退出倍数 → 更高 IRR 等）。

### 格式
- [ ] 硬编码输入为蓝色（0000FF）。
- [ ] 计算公式为黑色（000000）。
- [ ] 同一标签页链接为紫色（800080）。
- [ ] 跨标签页链接为绿色（008000）。
- [ ] 所有数字右对齐。
- [ ] 全文应用适当数字格式。
- [ ] 没有单元格显示错误值（#REF!、#DIV/0!、#VALUE!、#NAME?）。

### 逻辑合理性检查
- [ ] 数字数量级合理。
- [ ] 趋势合理（按预期增长、下降、稳定）。
- [ ] 没有明显错误值（应为正却为负、不可能的百分比等）。
- [ ] 关键输出处于该类分析的合理区间内。

## 应避免的常见错误

| 错误 | 会出什么问题 | 如何修复 |
|-------|-----------------|------------|
| 硬编码计算值 | 输入变化时模型不会更新 | 始终使用引用来源单元格的公式 |
| 复制后单元格引用错误 | 公式指向错误单元格 | 验证所有链接，使用适当 `$` 锚定 |
| 循环引用错误 | 模型无法计算 | 利息类计算使用期初余额，打破循环 |
| 章节不平衡 | 应匹配的合计不匹配 | 确保某一项是 plug（按差额计算） |
| 出现不可能的负余额 | 支付/使用超过可用金额 | 适当使用 MAX(0, ...) 或 MIN 函数 |
| IRR/回报错误 | 符号错误或区间不完整 | 检查现金流符号，并确保公式覆盖所有期间 |
| 敏感性表显示相同值 | 公式没有随输入变化 | 检查单元格引用，需要混合引用（$A5、B$4） |
| 滚动表无法勾稽 | 期初 ≠ 上期期末 | 验证期间之间的链接 |
| 符号约定不一致 | 增加项变成扣减项，或反之 | 全程遵循模板约定 |

## 与用户协作 — 逐章节检查点

* **如果模板结构不清楚**，先询问再继续。
* **如果用户要求与模板冲突**，确认用户偏好。
* **每完成一个主要章节后**，停止并与用户核验后再继续：
  - **资金来源与用途之后** → 展示已平衡表格，确认 plug 正确，取得签批后再构建经营模型。
  - **经营模型 / 预测之后** → 展示预测 P&L，确认增长率和利润率合理，取得签批后再做债务明细表。
  - **债务明细表之后** → 展示期初/期末余额和利息，确认 waterfall 逻辑，取得签批后再做回报分析。
  - **Returns（IRR/MOIC）之后** → 展示现金流序列和输出，确认符号和区间，取得签批后再做敏感性表。
  - **敏感性表之后** → 展示每个单元格都会变化，并确认基准情形落在预期位置。
* **如果核验中发现错误**，先修复再进入下一章节。
* **展示你的工作** - 有帮助时解释关键公式或假设。
* **绝不要在没有逐章节检查的情况下展示完整模型**；在来源处发现错误引用，比从断裂的 IRR 反向追踪更快。
