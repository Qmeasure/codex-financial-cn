# 审核电子表格

审核公式和数据的准确性，找出错误和常见问题。范围决定深度：可以只是对选区做快速公式检查，也可以对完整金融模型做完整性审计。

## 步骤 1：确定范围

如果用户已经给定范围，就使用该范围。否则**先询问用户**：

> 你希望我审核哪个范围？
> - **selection**：仅当前选中区域
> - **sheet**：仅当前活动 sheet
> - **model**：整个工作簿，包括金融模型完整性检查（BS 平衡、现金勾稽、滚动表、逻辑合理性）

**model** 范围最深入。对于 DCF、LBO、三表、并购模型、可比公司模型，或任何发送给客户/IC 前的一体化金融模型，都应使用该范围。

---

## 步骤 2：公式级检查（所有范围）

无论范围如何，都运行以下检查：

| 检查项 | 需要查找的问题 |
|---|---|
| 公式错误 | `#REF!`、`#VALUE!`、`#N/A`、`#DIV/0!`、`#NAME?` |
| 公式内硬编码 | `=A1*1.05` 中的 `1.05` 应该来自单元格引用 |
| 公式不一致 | 某个公式打破同一行/列相邻单元格的模式 |
| 区间偏移 | `SUM` / `AVERAGE` 漏掉首行或末行 |
| 被覆盖的公式 | 单元格看起来应为公式，但实际是硬编码值 |
| 循环引用 | 有意或无意的循环引用 |
| 跨 sheet 链接损坏 | 引用的单元格被移动或删除 |
| 单位/口径不匹配 | 千元与百万元混用，百分比被存成整数 |
| 隐藏行/标签页 | 可能包含覆盖值或过期计算 |

---

## 步骤 3：模型完整性检查（仅 model 范围）

如果范围是 **model**，先识别模型类型（DCF / LBO / 三表 / merger / 可比公司 / custom），再运行对应完整性检查。

### 3a. 结构审查

| 检查项 | 需要查找的问题 |
|---|---|
| 输入/公式分离 | 输入是否与计算清晰分离 |
| 颜色约定 | 蓝色=输入、黑色=公式、绿色=链接，或模型自有约定是否一致执行 |
| 标签页流向 | 顺序是否合理（假设 → IS → BS → CF → 估值） |
| 日期表头 | 各标签页是否一致 |
| 单位 | 是否一致（千、百万、实际金额） |

### 3b. 资产负债表

| 检查项 | 测试 |
|---|---|
| BS 是否平衡 | 总资产 = 总负债 + 权益（每个期间） |
| 留存收益滚动 | 期初留存收益 + 净利润 − 分红 = 期末留存收益 |
| 商誉/无形资产 | 是否来自收购假设（如适用 M&A） |

如果 BS 不平衡，**按期间量化差额并追踪断点**。在这个问题修复前，其他检查都不是优先级。

### 3c. 现金流量表

| 检查项 | 测试 |
|---|---|
| 现金勾稽 | CF 期末现金 = BS 现金（每个期间） |
| CF 求和 | CFO + CFI + CFF = 现金变动 |
| D&A 匹配 | CF 中的 D&A = IS 中的 D&A |
| CapEx 匹配 | CF 中的 CapEx 与 BS 中 PP&E 滚动表匹配 |
| 营运资本变化 | 符号与 BS 变动一致（ΔAR、ΔAP、ΔInventory） |

### 3d. 利润表

| 检查项 | 测试 |
|---|---|
| 收入构建 | 是否勾稽到分部/产品明细 |
| 税项 | 所得税费用 = 税前利润 × 税率（允许递延税调整） |
| 股数 | 是否勾稽到稀释股数表（期权、可转债、回购） |

### 3e. 循环引用

- 利息 → 债务余额 → 现金 → 利息，是 LBO/三表模型中常见的有意循环。
- 如为有意循环：核验迭代开关存在且可用。
- 如为无意循环：追踪循环路径，并标明如何断开。

### 3f. 逻辑与合理性

| 检查项 | 标记条件 |
|---|---|
| 增长率 | 收入增长超过 100% 且无解释 |
| 利润率 | 超出行业常见区间 |
| 终值占比过高 | TV 超过 DCF EV 约 75%（黄色预警） |
| Hockey-stick | 预测在远期年份不现实地陡增 |
| 复合增长 | EBITDA 到第 10 年复合到荒谬金额 |
| 边界情景 | 0% 或负增长、负 EBITDA、杠杆变负时模型失效 |

### 3g. 按模型类型检查的常见错误

**DCF：**
- 折现率应用到错误期间（年中 vs 年末）
- 终值没有折回现值
- WACC 使用账面价值而不是市场价值
- FCF 包含利息费用（应使用无杠杆 FCF）
- 重复计算税盾

**LBO：**
- 债务偿还与现金清扫机制不匹配
- PIK 利息没有滚入本金
- 管理层 rollover 没有反映到回报中
- 退出倍数应用到错误 EBITDA（LTM vs NTM）
- 费用/开支未从 Day 1 股权中扣除

**Merger：**
- 增厚/摊薄使用错误股数（交易前 vs 交易后）
- 协同效应没有分阶段体现
- 收购价格分摊不平衡
- 未包含现金机会成本对应的少收利息
- 交易费用未进入 sources & uses

**三表：**
- 营运资本变化符号错误
- 折旧与 PP&E 明细表不匹配
- 债务到期表与本金偿还不匹配
- 分红超过净利润且没有解释

## 步骤 4：报告

输出发现表：

| # | 工作表 | 单元格/区域 | 严重程度 | 类别 | 问题 | 建议修复 |
|---|---|---|---|---|---|---|

**严重程度：**
- **严重**：输出错误（BS 不平衡、公式损坏、现金无法勾稽）
- **警告**：存在风险（硬编码、公式不一致、边界情景失效）
- **提示**：风格/最佳实践问题（颜色编码、布局、命名）

对于**模型**范围，在前面加一行摘要：

> 模型类型：[DCF/LBO/三表/...] — 总体：[干净 / 轻微问题 / 重大问题] — [N] 个严重问题、[N] 个警告、[N] 个提示

**未经用户确认不要修改任何内容**。先报告，用户要求修复后再改。

## 说明

- **先看 BS 是否平衡**。如果 BS 不平衡，下游全部结果都可疑。
- **硬编码覆盖值是静默错误的第一来源**。要积极搜索。
- **符号约定错误**（现金流出为正还是为负）极其常见。
- 如果模型使用 VBA 宏，说明哪些宏驱动计算无法仅凭公式审计。
