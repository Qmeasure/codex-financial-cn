# 首次覆盖报告质量控制清单
> 图表样式 Gate：生成或审查图表前必须读取本 skill 的本地格式 reference；柱状图、堆叠柱状图、分组柱状图默认关闭纵坐标横向网格线，除非用户明确要求或图表类型必须依赖网格线，否则不得显示 major/minor gridlines。DOCX、PPTX、PNG/JPG 图表都必须在 QA 中检查该项。


交付首次覆盖报告前，核验以下所有项目均已完成。

## 关键最低要求 - 报告必须满足

**关键：出现以下任一情况，不得交付：**
- ❌ DOCX 报告少于 30 页 → 不完整
- ❌ 嵌入图表少于 25 张 → 不完整
- ❌ 综合表格少于 12 张 → 不完整
- ❌ 少于 10,000 字 → 不完整
- ❌ 没有 XLS 财务模型 → 缺少交付物
- ❌ 图表只是文字描述，不是真实 PNG/JPG 文件 → 重大失败

## 交付物清单

- [ ] 已创建 DOCX 报告文件
- [ ] 已创建 XLS 财务模型文件
- [ ] 两个文件均正确命名：`[Company]_Initiation_Report_[Date].docx` 和 `[Company]_Financial_Model_[Date].xlsx`

## DOCX 报告 - 长度与内容

**长度核验：**
- [ ] 报告为 30-50 页（在最终文档中统计页数）
- [ ] 字数为 10,000-15,000 字
- [ ] 如果少于 30 页：停止并补充内容

**视觉元素：**
- [ ] 嵌入 25-35 张图表（实际数量：_____ 张）
- [ ] 所有图表都是真实 PNG/JPG 图片文件（不是文字描述）
- [ ] 包含 12-20 张综合表格（实际数量：_____ 张）
- [ ] 图表和表格穿插于全文，而不是集中放在末尾

**图表要求：**
- [ ] 按产品收入图：Stacked Area 格式 ✓
- [ ] 按地区收入图：Stacked Bar 格式 ✓
- [ ] DCF 敏感性：带颜色编码的双变量 Heat Map ✓
- [ ] 估值 football field：横向条形图 ✓
- [ ] 其他所有图表均为真实图片文件 ✓

**表格要求：**
- [ ] 完整利润表（40-50 行），含 5 年历史 + 5 年预测
- [ ] 完整现金流量表（30-40 行）
- [ ] 完整资产负债表（35-45 行）
- [ ] 按产品收入表（20-30 行）
- [ ] 按地区收入表（15-20 行）
- [ ] 按渠道收入表（10-15 行）
- [ ] 可比公司表，含统计摘要（max/75th/median/25th/min）
- [ ] DCF 计算表（30-40 行）
- [ ] WACC 计算表（8-10 行）
- [ ] 两张敏感性表
- [ ] 2-3 张额外财务/竞争表

## DOCX 报告 - 结构

**第 1 页要求：**
- [ ] 存在“首次覆盖”页眉（不是“公司更新”）
- [ ] 标题聚焦投资逻辑（不是“强劲的第四季度业绩”这类事件驱动标题）
- [ ] 评级框包含评级、股价、目标价、52 周区间、市值、EV
- [ ] 3-4 个段落长度要点，使用 ■ 字符和加粗标题
- [ ] 财务与估值指标表包含 2-3 年历史、2 年预测
- [ ] 表格中实际值使用 “A” 后缀，预测值使用 “E” 后缀
- [ ] 所有视觉元素都有来源行

**内容章节：**
- [ ] 目录（第 2 页）
- [ ] 投资逻辑与风险（3-5 页）
- [ ] 公司概览（6-12 页），包括：
  - [ ] 公司描述
  - [ ] 历史和里程碑
  - [ ] 管理层 bio（3-4 名高管，每人 300-400 字）
  - [ ] 产品/服务详情
  - [ ] 竞争格局
- [ ] 财务分析与预测（10-15 页）
- [ ] 估值分析（8-12 页）
- [ ] 假设章节（2,000-3,000 字，记录全部预测假设）
- [ ] 情景分析（1,500-2,000 字，含 Bull/Base/Bear 参数）
- [ ] 附录包含数据来源与参考页

## DOCX 报告 - 格式

**图表和表格格式：**
- [ ] 每张图表上方都有图题：“图 X - [公司] [描述性标题]”
- [ ] 每个 Exhibit 下方都有单一主来源行：“来源：[含日期的具体来源]”
- [ ] Exhibit 来源行默认 6pt、最大 7pt；如有链接，链接文本也使用同一小字号
- [ ] 图表连续编号（图 1、2、3... 无跳号）
- [ ] 每张表都有带底色的表头行
- [ ] 每张表底部都有单一主来源行
- [ ] 所有年份使用 “A” 表示 actual，使用 “E” 表示 estimate

**专业格式：**
- [ ] 全篇字体一致；中文材料优先使用中文字体栈，英文/数字可使用 Calibri、Arial 或类似字体
- [ ] 页眉和页脚包含页码
- [ ] 高密度布局：页面覆盖率 60-80%，尽量减少空白
- [ ] 每页同时包含文字和视觉元素（图表或表格）
- [ ] 使用专业商业报告模板

## 引用与来源 ⭐⭐⭐ 关键

**来源归属：**
- [ ] 每个 Exhibit 都有具体来源，含文档名称和日期
- [ ] 完整来源清单放在数据来源章节，不堆在 Exhibit 下方
- [ ] 全文关键统计数据都有带来源的脚注
- [ ] 不得只写泛泛的 “Company data”，必须具体

**超链接：** ⭐⭐⭐ 强制
- [ ] 所有 URL 都是可点击超链接（不是纯文本）
- [ ] SEC 披露文件链接到 EDGAR viewer；A股/港股材料链接到交易所或公司公告页
- [ ] 业绩会文字稿有超链接（Seeking Alpha 或公司 IR）
- [ ] 新闻稿链接到公司 IR 页面
- [ ] 演示材料链接到 PDF URLs
- [ ] 行业报告有超链接（如公开可得）
- [ ] 订阅数据（Bloomberg、FactSet）注明“需要订阅”
- [ ] 文档中任何位置都不显示裸 URL，全部格式化为超链接
- [ ] 测试 3-5 个样例超链接，确保可用（Ctrl+Click）

**参考页：**
- [ ] 报告末尾有 “数据来源与参考” 页
- [ ] 列出报告使用的所有来源
- [ ] 来源按类别组织（SEC Filings、Earnings Transcripts 等）
- [ ] 每个来源都有日期
- [ ] 每个来源都有可点击超链接（如适用）

## XLS 财务模型 - 结构

**文件结构：**
- [ ] Excel 工作簿包含 15+ 个 tabs
- [ ] 标签页包括：执行摘要、假设、历史财务数据、收入模型、经营费用、利润表、资产负债表、现金流量表、支持性明细表、DCF 估值、可比公司分析、先例交易、情景、敏感性分析、图表

**格式：**
- [ ] 硬编码输入使用蓝色文本
- [ ] 公式使用黑色文本
- [ ] 链接到其他 sheet 的内容使用绿色文本
- [ ] 使用带边框和底色的专业格式
- [ ] Section headers 和标签清楚

**模型功能：**
- [ ] 所有数字联动（修改假设 → 整个模型更新）
- [ ] DCF 链接到假设和预测
- [ ] 没有循环引用或错误
- [ ] 所有重要单元格/ranges 已命名
- [ ] 敏感性表可动态运行

## XLS 财务模型 - 内容

**预测：**
- [ ] 3-5 年历史数据
- [ ] 5 年前瞻预测（FY+1 至 FY+5）
- [ ] 收入按产品、地域、渠道拆分
- [ ] 完整 P&L，40-50 个科目
- [ ] 完整现金流，30-40 个科目
- [ ] 完整资产负债表，35-45 个科目

**估值：**
- [ ] 完整 DCF 模型，展示全部计算
- [ ] WACC 计算，包含全部组成部分
- [ ] Terminal value 计算
- [ ] 可比公司分析（5-10 家）
- [ ] 可比交易分析（5-10 笔交易）
- [ ] 情景分析（Bull/Base/Bear）
- [ ] 两张敏感性表

## 跨文件一致性

**关键**：DOCX 和 XLS 之间的数字必须完全一致

- [ ] 两个文件中的收入数字一致
- [ ] 两个文件中的 EPS 数字一致
- [ ] 两个文件中的利润率百分比一致
- [ ] 两个文件中的估值数字一致
- [ ] 两个文件中的目标价一致
- [ ] 两个文件中的所有预测年份一致

**核验方法**：在 DOCX 报告和 XLS 模型之间抽查 10-15 个关键数字。

## 内容质量

**投资逻辑：**
- [ ] 3-5 个清晰投资逻辑支柱
- [ ] 每个支柱均有具体数据和量化支持
- [ ] 每个支柱的财务影响已量化
- [ ] 催化剂已识别并配有时间线

**分析深度：**
- [ ] 商业模式分析全面
- [ ] 竞争评估详细
- [ ] 已分析 3-5 年财务趋势
- [ ] 识别并量化 8-12 项风险
- [ ] 已分析管理团队（每名高管 300-400 字）

**假设：**
- [ ] 用 2,000-3,000 字记录全部假设
- [ ] 按类别/地域拆分的收入增长假设
- [ ] 利润率假设包含展示驱动因素的 bridge
- [ ] 营运资本假设
- [ ] CapEx 假设
- [ ] 每项假设都有具体量化

**情景：**
- [ ] 情景分析 1,500-2,000 字
- [ ] Bull case 有具体参数和催化剂
- [ ] Base case 有详细理由
- [ ] Bear case 有具体触发因素
- [ ] 每个情景都有概率评估

## 写作质量

**风格：**
- [ ] 以数字开头（写“收入增长 15% 至 12 亿美元”，不要写“收入表现强劲”）
- [ ] 使用 “vs.”，不要使用 “versus”
- [ ] 直接、简洁
- [ ] 全篇保持专业机构语气
- [ ] 不使用非正式语言

**准确性：**
- [ ] Ticker symbol 无拼写错误
- [ ] 公司名称无拼写错误
- [ ] 所有日期准确
- [ ] 所有计算已核验
- [ ] 图表与文字描述一致
- [ ] 所有数字格式正确（货币符号、百分号、千分位）

## 交付前最终检查

执行以下快速最终审阅：

1. **交付物**：DOCX 和 XLS 文件都已创建 ✓
2. **长度**：DOCX 为 30-50 页 ✓
3. **图表**：嵌入 25-35 个真实 PNG/JPG 文件 ✓
4. **表格**：包含 12-20 张综合表格 ✓
5. **字数**：10,000-15,000 字 ✓
6. **超链接**：测试 3-5 个超链接，全部可用 ✓
7. **交叉检查**：抽查 10 个数字，DOCX 与 XLS 一致 ✓
8. **第 1 页**：存在“首次覆盖”页眉 ✓

如果任何项目失败，不得交付。返回修复。
