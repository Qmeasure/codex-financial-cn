# 竞争格局 Mapping

构建完整竞争分析材料。这是一个两阶段流程：先收集需求并获得大纲批准，再开始制作。

## 环境检查

本 skill 可在 PowerPoint add-in 和聊天环境中使用。开始前先识别当前环境：具体操作方式不同，但工作流相同。

- **Add-in**：材料已实时打开，直接在其中构建幻灯片。
- **Chat**：生成 `.pptx` 文件，或基于用户上传的文件构建。

以下内容两种环境都适用。

## 阶段 1 — 界定分析范围

不同人对竞争分析的理解不同。在做任何研究或制作幻灯片之前，使用 `ask_user_question` 锁定用户真正想要什么。不要猜：20 页同业 benchmark 材料和 5 页市场地图都叫“竞争分析”，但形态完全不同。

尽量一轮问完（该工具最多支持 4 个问题）：

- **范围**：围绕单一目标公司展开？还是没有主角的多公司并列比较？
- **竞争对手集合**：哪些公司纳入范围？如果用户点名，必须严格使用这些公司。如果用户说“常见那几家”，先提出集合并确认。
- **受众与深度**：给熟悉该领域的人快速阅读，还是完整入门材料？这决定是否需要市场规模、行业经济性和历史背景，还是可以直接进入比较。
- **投资语境**：是否需要牛市/基准/熊市场景和关键判断标识？这对应下方步骤 9；如果只是战略审阅而非投资逻辑，则跳过。

如果用户上传了含竞争对手数据的 Excel/CSV，先确认哪些列对应哪些指标，再开始提取数字。源文件保真很重要：按原值使用，不要重新计算或重新四舍五入。

## 阶段 2 — 先大纲、后批准、再制作

**大纲获批前不要创建幻灯片。** 先提出幻灯片标题和每页一句内容说明，展示给用户并获得确认。竞争格局材料通常有 10-20 页，内容相互咬合；如果第 4 页方向错了再返工会很贵。大纲才是低成本迭代点。

提出大纲时，`ask_user_question` 适合用来确认结构性决策：选择哪种定位图（2×2 矩阵 / 雷达图 / 分层图，见步骤 5），如何给竞争对手分组（按商业模式 / 分部 / 姿态，见步骤 4）。这些偏好判断用户通常会有明确意见。

## 全篇适用标准

### 忠实遵循 prompt

用户明确指定的内容是要求，不是建议：
- **幻灯片标题和章节名称**：使用精确措辞。如果用户说“概览与竞争范围”，不要替换成“FY2024 竞争格局”。
- **图表 vs. 表格**：两者不可互换。“嵌入式图表”表示带数据标签的真实图表对象，不是格式化表格。
- **完整数据序列**：如果用户列出 7 家竞争对手，就包含全部 7 家。如果用户给出 2015-2025，就包含每一年。
- **精确值和比率**：“超过 DoorDash 4:1、Lyft 8:1”表示必须使用这些比率，不要改成“Lyft 的 7.6 倍”。

### 来源质量：来源冲突时

1. 10-K / 年报（经审计）
2. 业绩会 / 投资者演示（管理层评论）
3. 卖方研究（分析师预测，对非上市公司规模估算有用）
4. 行业报告（McKinsey、Gartner 等，用于市场规模和趋势）
5. 新闻（仅用于近期进展，并需用一手来源核验）

### 数据可比性

- 所有竞争对手指标来自同一财年；例外需明确标注（例如“FY24” vs “H1 2024”）
- 各竞争对手使用相同指标定义
- 跨境比较默认换算为美元；注明汇率和日期。A股/港股材料按用户要求保留人民币/港元时，必须显式标注币种和口径
- 缺失数据显示为 “-” 或 “N/A”；估算值加 “[E]” 标记，绝不留空
- 每个数字都有引用：“[Company] [Document] ([Date])”

### 设计

- **幻灯片标题应是洞察，不是标签。** 写“规模领先者正在拉开与利基玩家的差距”，不要写“竞争分析”。
- **Signposts 要量化。** 写“利润率低于 40%”，不要写“利润率下降”。
- **评级要显示实际数值。** 写“●●● 1,600 亿美元”，不要只写“●●●”。
- **图表必须是真实图表对象**，不要把文本表格包装成图表样式。

**排版**：显式设置，不依赖默认值：
- 幻灯片标题：28-32pt，加粗
- Section headers：18-20pt，加粗
- 正文：14-16pt（绝不低于 14pt）
- 表格文本：14pt
- 来源/脚注：14pt，灰色
- 同类元素在整份材料中保持同一字号

**图表：**
- 图例放在图表边界内，不要漂浮在绘图区上方
- 饼图（≤6 个扇区）使用右侧图例；折线/柱状图（≤4 个系列）使用底部图例
- 超过 6 个系列时，拆成多个图表或改用表格
- 饼图要在扇区上显示百分比，不要只在图例中显示

**表格：**
- 表头行浅灰底、加粗
- 数字右对齐，文本左对齐
- 单元格留足 padding，文字不要贴边

**颜色：** 最多 2-3 种。保持克制：海军蓝、灰色和一个强调色。全篇同一颜色含义保持一致。

### 严格项与灵活项

| 始终遵守 | 视情况处理 |
|---|---|
| 用户指定标题/章节时逐字保留 | 未指定时可使用更有洞察的标题 |
| 用户说图表就用图表，说表格就用表格 | 未指定时自行选择可视化类型 |
| 用户列出的每个竞争对手/数据点都要包含 | 未指定时确定竞争对手数量 |
| 用户指定的精确值必须保留 | 未指定精度时可合理四舍五入 |
| 标题必须不溢出 | 竞争对手分类数量 |
| 不允许元素重叠 | 比较哪些维度 |

## 分析工作流

### 步骤 0 — 行业定义性指标

先回答一个问题：这个行业真正运行在 3-5 个什么核心指标上？对所有竞争对手一致使用这些指标。

| 行业 | 关键指标 |
|---|---|
| SaaS | ARR、NRR、CAC 回本周期、LTV/CAC、Rule of 40 |
| 支付 | GPV、抽佣率、挂载率、交易利润率 |
| 市场平台 | GMV、take rate、买家/卖家比、复购率 |
| 零售 | 同店销售、库存周转、每平方英尺销售额 |
| 物流 | 货量、单位成本、准时交付率、产能利用率 |

如果行业未列出，选择投资者和经营者实际用于 benchmark 的指标。

### 步骤 1 — 市场背景

市场规模、增长、驱动因素、逆风。必须附来源。

正确：“Embedded payments 2024 年市场规模为 800-1,000 亿美元，CAGR 为 20-25%（McKinsey 2024）”  
错误：“市场规模大且快速增长”

### 步骤 2 — 行业经济性

映射价值如何流动。方法取决于行业结构：
- **垂直结构**：价值链层级，以及各层典型利润率
- **平台/网络**：生态参与方，以及它们之间的价值流
- **分散行业**：整合动态，以及不同规模下的利润率差异

### 步骤 3 — 目标公司画像

```
| 指标 | 值 |
|---|---|
| 收入 | $4.96B |
| 增长 | 同比 +26% |
| 毛利率 | 45% |
| 盈利能力 | $373M Adj. EBITDA |
| 客户数 | 134K |
| 留存率 | 92% |
| 市场份额 | ~15% |
```

多分部公司增加拆分表：

```
| 分部 | 收入 | 收入同比 | 收入占比 | EBITDA | EBITDA 同比 | 利润率 |
|---|---|---|---|---|---|---|
| Seg A | $25.1B | +26% | 57% | $6.5B | +31% | 26% |
| Seg B | $13.8B | +31% | 31% | $2.5B | +64% | 18% |
| Seg C | $5.1B | -2% | 12% | -$74M | -16% | -1% |
| Total | $44.0B | +18% | 100% | $6.5B* | - | 15% |
```
*如适用，注明总部成本

### 步骤 4 — 竞争对手映射

按最合适的视角分组（如果用户未指定，这是适合用 `ask_user_question` 确认的决策）：
- 按商业模式：平台 / 垂直 / 横向
- 按分部：enterprise / SMB / consumer
- 按竞争姿态：直接 / 相邻 / 新兴
- 按来源：既有玩家 / 颠覆者 / 新进入者

### 步骤 5 — 定位可视化

| 类型 | 适用场景 |
|---|---|
| 2×2 matrix | 两个主导竞争因素 |
| Radar/spider | 多因素比较 |
| Tier diagram | 竞争对手自然聚为战略组 |
| Value chain map | 垂直行业 |
| Ecosystem map | 平台型市场 |

各行业 2×2 轴组合见 `references/frameworks.md`。

### 步骤 6 — 竞争对手深度分析

每个竞争对手两张表。

**指标：**
```
| 指标 | 值 |
|---|---|
| 收入 | $X.XB |
| 增长 | 同比 +XX% |
| 毛利率 | XX% |
| 市值 | $X.XB |
| 盈利能力 | $XXXM EBITDA |
| 客户数 | XXK |
| 留存率 | XX% |
| 市场份额 | ~XX% |
```

**定性：**
```
| 类别 | 评估 |
|---|---|
| 业务 | 做什么（1 句话） |
| 优势 | 2-3 个要点 |
| 劣势 | 2-3 个要点 |
| 战略 | 当前优先事项 |
```

### 步骤 7 — 横向比较分析

```
| 维度 | Company A | Company B | Company C |
|---|---|---|---|
| Scale | ●●● $160B | ●●○ $45B | ●○○ $8B |
| Growth | ●●○ +26% | ●●● +35% | ●●○ +22% |
| Margins | ●●○ 7.5% | ●○○ 3.2% | ●●● 15% |
```

### 步骤 8 — 战略背景

M&A 交易（multiples、交易理由）、合作伙伴趋势、融资模式、监管进展。M&A 交易表格式见 `references/schemas.md`。

### 步骤 9 — 综合判断

**护城河评估**：对每个竞争对手在以下维度评为 Strong / Moderate / Weak：

| 护城河 | 评估内容 |
|---|---|
| 网络效应 | 用户/供应商 flywheel 强度；跨边 vs 同边网络效应 |
| 转换成本 | 技术集成深度、合同锁定、行为习惯 |
| 规模经济 | 放量后的单位成本优势、最小有效规模 |
| 无形资产 | 品牌、专有数据、监管牌照、专利 |

**必需综合元素：**
- 持久优势（难以复制）：映射到护城河类别
- 结构性脆弱点（难以修复）
- 当前状态 vs. 发展轨迹

**投资语境**（如果阶段 1 定义范围时确认不需要，则跳过）：

```
| 情景 | 概率 | 关键驱动因素 |
|---|---|---|
| Bull | 30% | 市场份额提升、利润率扩张 |
| Base | 50% | 当前轨迹延续 |
| Bear | 20% | 竞争压力、利润率压缩 |
```

## 质量检查清单

完成前检查：

**Prompt 忠实度**
- 幻灯片标题与用户指定内容逐字一致
- 用户说图表的地方用图表，说表格的地方用表格
- 用户列出的每个竞争对手/年份/数据点都已包含
- 精确值和格式按用户指定保留

**数据一致性**
- 源文件数值直接提取，不重新计算
- 同一指标在所有出现位置保持同一数值
- 小数精度与来源一致

**布局**
- 标题完整放入，不溢出
- 没有元素重叠
- 所有文本都在容器内，没有裁切

**内容**
- 每个数字都有引用
- 所有指标来自同一财政期间，或已明确标注例外
- 幻灯片标题表达洞察，而不是只写主题
- 图表是真实图表对象

对每页运行标准视觉校验检查；这能发现仅回读 XML 时看不到的重叠、溢出和低对比度文本问题。
