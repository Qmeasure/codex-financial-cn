# 三表财务模型模板补全

补全并填充集成财务模型模板，确保利润表、资产负债表和现金流量表之间正确联动。

## ⚠️ 关键原则 — 填充任何模板前请先阅读

**环境 — Office JS 与 Python：**
- **如果在 Excel 内运行（Office 加载项 / Office JS）：** 直接使用 Office JS。通过 `range.formulas = [["=D14*(1+Assumptions!$B$5)"]]` 写入公式；派生单元格绝不要用 `range.values`。无需单独重算，Excel 会原生计算。使用 `context.workbook.worksheets.getItem(...)` 在工作表之间导航。
- **如果生成独立 .xlsx 文件：** 使用 Python/openpyxl。写入 `ws["D15"] = "=D14*(1+Assumptions!$B$5)"`，然后在交付前运行 `recalc.py`。
- **Office JS 合并单元格陷阱：** 不要先调用 `.merge()` 再在合并区域上设置 `.values`；这会抛出 `InvalidArgument`，因为区域仍报告合并前维度。正确做法是只把值写入左上角单元格，再合并并设置整个区域格式：`ws.getRange("A1").values = [["INCOME STATEMENT"]]; const h = ws.getRange("A1:G1"); h.merge(); h.format.fill.color = "#1F4E79";`
- 以下所有原则在两种环境中完全相同。

**公式优先于硬编码（不可协商）：**
- 每个预测单元格、滚动表、联动项和小计都必须是 Excel 公式；绝不是预先计算好的值。
- 使用 Python/openpyxl 时，写公式字符串（`ws["D15"] = "=D14*(1+Assumptions!$B$5)"`），不要写计算结果（`ws["D15"] = 12500`）。
- 唯一应包含硬编码数字的单元格是：(1) 历史实际值，(2) 假设标签页中的假设驱动项。
- 如果发现自己在 Python 中计算一个值并写入单元格，立即停止。应写入公式。
- 原因：当情景切换或假设变化时，模型必须能联动。硬编码会静默破坏所有下游完整性检查。

**与用户逐步核验：**
1. **映射模板后** → 向用户展示你识别出的标签页/章节，并在改动任何单元格前确认。
2. **填充历史值后** → 向用户展示历史数据模块，并确认数值/期间与来源数据一致。
3. **构建利润表预测后** → 运行小计检查，向用户展示预测利润表，确认后再进入资产负债表。
4. **构建资产负债表后** → 向用户展示每个期间的平衡检查（Assets = L+E），确认后再进入现金流量表。
5. **构建现金流量表后** → 向用户展示现金勾稽（CF ending cash = BS cash），确认后再收尾。
6. **不要端到端填完整个模型后才展示**；应在每张报表处停下展示工作，尽早发现错误。

## 格式 — 专业蓝/灰色板（默认，除非模板/用户另有指定）

**保持颜色克制。** 单元格填充只使用蓝色和灰色。不要引入绿色、黄色、橙色或多种强调色；干净模型需要克制。

| 元素 | 填充 | 字体 |
|---|---|---|
| 章节标题（IS / BS / CF 标题） | 深蓝 `#1F4E79` | 白色加粗 |
| 列表头（FY2024A、FY2025E 等） | 浅蓝 `#D9E1F2` | 黑色加粗 |
| 输入单元格（历史值、假设驱动项） | 浅灰 `#F2F2F2` 或白色 | 蓝色 `#0000FF` |
| 公式单元格 | 白色 | 黑色 |
| 跨表链接 | 白色 | 绿色 `#008000` |
| 检查行 / 关键合计 | 中蓝 `#BDD7EE` | 黑色加粗 |

**总共就是 3 种蓝色 + 1 种灰色 + 白色。** 如果模板有自己的配色方案，遵循模板。

字体颜色表示单元格“是什么”（输入/公式/链接）。填充颜色表示你“在哪里”（标题/数据/检查）。

## 模型结构

### 识别模板标签页组织方式

不同模板的标签页命名和组织方式不同。填充前，应审阅所有标签页以理解模板结构。以下是常见标签页名称及其典型内容：

| 常见标签页名称 | 应查找的内容 |
|------------------|----------------------|
| IS, P&L, 利润表 | 利润表 |
| BS, 资产负债表 | 资产负债表 |
| CF, CFS, 现金流量表 | 现金流量表 |
| WC, Working Capital | 营运资本明细表 |
| DA, D&A, Depreciation, PP&E | 折旧与摊销明细表 |
| 债务，债务明细表 | 债务明细表 |
| NOL, Tax, DTA | 净经营亏损明细表 |
| 假设、输入、驱动项 | 驱动假设和输入 |
| Checks, Audit, Validation | 错误检查仪表盘 |

**模板审阅清单**
- 识别模板中存在哪些标签页（并非所有模板都包含每个明细表）。
- 记录上表未列出的模板特定标签页。
- 理解标签页依赖关系（例如哪些明细表流入主报表）。
- 找到每个标签页上的输入单元格与公式单元格。

### 理解模板结构

填充模板前，熟悉既有布局，确保数据进入正确位置且公式保持完整。

**识别行结构**
- 找到每个标签页顶部的模型标题。
- 识别章节标题及其视觉分隔。
- 找到说明 $ millions、%、x 等单位的单位行。
- 注意区分 Actuals 与 Estimates 期间的列表头。
- 确认期间标签（例如 FY2024A、FY2025E）。
- 识别输入单元格与公式单元格（通常通过字体颜色区分）。

**识别列结构**
- 确认最左列的行项目标签。
- 验证历史年份位于预测年份之前。
- 注意分隔历史期与预测期的视觉边框。
- 检查所有标签页的列顺序是否一致。

**使用命名区域**
模板经常用命名区域表示关键输入和输出。输入数据前：
- 审阅模板中的既有命名区域（Excel 中 Formulas → Name Manager）。
- 常见命名区域包括：收入增长率、成本百分比、关键输出（净利润、EBITDA、Total Debt、Cash）、情景选择器单元格。
- 确保输入写入会流入这些命名区域的单元格。

### 预测期
- 模板通常从最后一个历史年度向前预测 5 年。
- 验证历史列（A）和预测列（E）是否清晰分开。
- 确认列使用财年标记法（例如 FY2024A、FY2025E）。

## 利润率分析

**说明：仅当用户要求或模板明确要求时，才执行以下利润率分析。如果没有提示，跳过本节。**

在利润表（IS）标签页计算并展示盈利能力利润率，用于跟踪经营效率并支持同业比较。

### 应纳入的核心利润率

| 利润率 | 公式 | 衡量内容 |
|--------|---------|------------------|
| 毛利率 | 毛利 / 收入 | 定价能力、生产效率 |
| EBITDA 利润率 | EBITDA / 收入 | 核心经营盈利能力 |
| EBIT Margin | EBIT / 收入 | 扣除 D&A 后的经营盈利能力 |
| 净利润 Margin | 净利润 / 收入 | 最终盈利能力 |

### 带利润率的利润表布局

将利润率百分比直接展示在每个利润行项目下方：
- 毛利下方展示毛利率 %。
- EBIT 下方展示 EBIT Margin %。
- EBITDA 下方展示 EBITDA 利润率 %。
- 净利润下方展示净利润 Margin %。

## 信用指标

**说明：仅当用户要求或模板明确要求时，才执行以下信用分析。如果没有提示，跳过本节。**

在资产负债表（BS）标签页计算并展示信用/杠杆指标，用于评估财务健康、债务容量和契约合规。

### 应纳入的核心信用指标

| 指标 | 公式 | 衡量内容 |
|--------|---------|------------------|
| 总债务 / EBITDA | 总债务 / LTM EBITDA | 杠杆倍数 |
| 净债务 / EBITDA | （总债务 - 现金）/ LTM EBITDA | 扣除现金后的净杠杆 |
| 利息覆盖倍数 | EBITDA / 利息费用 | 偿债能力 |
| 债务 / 总资本 | 总债务 /（总债务 + 权益） | 资本结构 |
| 债务 / 权益 | 总债务 / 总权益 | 财务杠杆 |
| 流动比率 | 流动资产 / 流动负债 | 短期流动性 |
| 速动比率 | （流动资产 - 存货）/ 流动负债 | 即时流动性 |

### 信用指标层级检查

验证上行情景显示最强信用画像：
- 杠杆：上行情景 < 基准情景 < 下行情景（越低越好）。
- 覆盖倍数：上行情景 > 基准情景 > 下行情景（越高越好）。
- 流动性：上行情景 > 基准情景 > 下行情景（越高越好）。

### 契约合规跟踪

如果已知债务契约，添加明确合规检查，将实际指标与契约阈值比较。

## 情景分析（基准 / 上行 / 下行）

在假设标签页使用情景切换器（下拉框），并配合 CHOOSE 或 INDEX/MATCH 公式。

| 情景 | 说明 |
|----------|-------------|
| 基准情形 | 管理层指引或一致预期 |
| 上行情景 | 高于指引的增长、利润率扩张 |
| 下行情景 | 低于趋势的增长、利润率压缩 |

**要敏感性测试的关键驱动项**：收入增长、毛利率、SG&A %、DSO/DIO/DPO、CapEx %、利率、税率。

**情景审计检查**：切换器能切换所有报表；所有情景下 BS 平衡；现金勾稽一致；层级成立（NI、EBITDA、FCF、利润率满足上行情景 > 基准情景 > 下行情景）。

## 完成模型模板

本节提供完成任何三表财务模型模板的一般指引，同时保留既有公式并确保数据完整性。

### 步骤 1：分析模板结构

输入任何数据前，应彻底审阅模板，理解其架构：

**识别输入单元格与公式单元格**
- 寻找区分输入单元格和公式单元格的视觉线索（字体颜色、单元格底色）。
- 常见约定：蓝色字体 = 输入，黑色字体 = 公式，绿色字体 = 其他工作表链接。
- 使用 Excel 的 Trace Precedents/Dependents（Formulas → Trace Precedents）理解单元格关系。
- 检查是否存在控制关键输入的命名区域（Formulas → Name Manager）。

**映射模板流转**
- 识别哪些标签页流入其他标签页（例如假设 → IS → BS → CF）。
- 记录支持性明细表及其与主报表的联动。
- 填充前记录模板的具体行项目和结构。

### 步骤 2：填入数据且不破坏公式

**数据录入黄金规则**

| 规则 | 说明 |
|------|-------------|
| 只编辑输入单元格 | 除非有意替换公式，否则绝不覆盖含公式的单元格 |
| 保留单元格引用 | 复制数据时使用 Paste Values（Ctrl+Shift+V），避免用来源格式覆盖公式 |
| 匹配模板单位 | 输入数据前确认模板使用千、百万还是实际值 |
| 尊重符号约定 | 遵循模板既有符号约定（例如费用为正还是为负） |
| 检查循环引用 | 如果模板使用迭代计算，确保启用迭代计算 |

**安全数据录入流程**
1. 识别指定为输入的准确单元格（通常有高亮或标签）。
2. 先录入历史数据，再验证这些期间的公式是否正确计算。
3. 录入会驱动预测计算的假设驱动项。
4. 审阅计算输出，确认公式按预期运行。
5. 如果必须修改公式单元格，修改前记录原公式。

**处理预置公式**
- 如果公式引用了尚未填充的单元格，在所有输入完成前，临时错误（#REF!、#DIV/0!）是可预期的。
- 如果公式产生异常结果，追踪先例单元格以识别缺失或错误输入。
- 未检查所有标签页上的公式依赖前，绝不要删除行/列。

### 步骤 3：验证公式

**公式完整性检查**

依赖模板输出前，验证公式是否正常运行：

| 检查类型 | 方法 |
|------------|--------|
| 追踪先例 | 选择公式单元格 → Formulas → Trace Precedents，验证其引用正确输入 |
| 追踪从属 | 验证关键输入是否流向预期输出单元格 |
| 计算公式 | 使用 Formulas → Evaluate Formula 逐步检查复杂计算 |
| 检查硬编码 | 预测公式应引用假设，而不是包含硬编码值 |
| 用已知值测试 | 输入简单测试值，验证公式输出符合预期 |
| 跨表一致性 | 确保所有预测期间使用相同公式逻辑 |

**常见公式问题**
- 复制跨期间公式时，混合绝对/相对引用导致结果错误。
- 外部文件或被删除区域的链接断裂（#REF! 错误）。
- 收入爬坡前早期期间出现除零错误（#DIV/0!）。
- 循环引用警告（利息计算中可能是有意设计）。
- 预测列之间公式不一致（用 Ctrl+\ 查找差异）。

**验证跨表联动**
- 确认多个标签页出现的值是链接而非重复录入。
- 验证明细表合计勾稽到主报表对应行项目。
- 检查所有标签页期间标签是否对齐。

### 步骤 4：按工作表做质量检查

填充模板后，对每张表执行以下校验：

**利润表（IS）质量检查**
- 历史期间收入数字与来源数据一致。
- 所有费用行项目加总到报告合计。
- 小计（毛利、EBIT、EBT、净利润）计算正确。
- 税费计算逻辑恰当（能正确处理亏损）。
- 预测驱动项引用假设标签页（无硬编码）。
- 期间环比变化方向合理。

**资产负债表（BS）质量检查**
- 每个期间 Assets = Liabilities + Equity（首要检查）。
- 现金余额与现金流量表期末现金一致。
- 营运资本科目勾稽到支持性明细表（如适用）。
- 留存收益正确滚动：Prior RE + 净利润 - Dividends +/- Adjustments = Ending RE。
- 债务余额勾稽到债务明细表（如适用）。
- 所有资产负债表项目符号适当（资产为正，大多数负债为正）。

**现金流量表（CF）质量检查**
- CFO 顶部净利润与利润表净利润一致。
- 非现金加回项（D&A、SBC 等）勾稽到来源明细表/报表。
- 营运资本变动符号正确（资产增加 = 现金流出 = 负数）。
- CapEx 勾稽到 PP&E 明细表或固定资产滚动表。
- 融资活动勾稽到 BS 上债务和权益科目的变化。
- 期末现金与资产负债表现金一致。
- 期初现金等于上一期期末现金。

**支持性明细表质量检查**
- 期初余额等于上一期期末余额。
- 滚动逻辑完整（Beginning + Additions - Deductions = Ending）。
- 明细表合计勾稽到主报表行项目。
- 计算中使用的假设与假设标签页一致。

### 步骤 5：跨报表完整性检查

验证单张表后，确认三张报表已正确集成：

| 检查 | 公式 | 预期结果 |
|-------|---------|-----------------|
| 资产负债表平衡 | Assets - Liabilities - Equity | = 0 |
| 现金勾稽 | CF Ending Cash - BS Cash | = 0 |
| 净利润联动 | IS 净利润 - CF Starting 净利润 | = 0 |
| 留存收益 | Prior RE + NI - Dividends - BS Ending RE | = 0（按 SBC/其他项目需要调整） |

### 步骤 6：最终审阅

认为模型完成前：
- 逐一切换所有情景（如适用），验证每种情景下检查均通过。
- 审阅并解决或记录所有 #REF!、#DIV/0!、#VALUE! 和 #NAME? 错误。
- 确认所有输入单元格都已填充（搜索占位值）。
- 验证所有标签页单位一致。
- 进一步修改前保存一个干净版本。

### 循环引用处理

利息费用会产生循环：Interest → 净利润 → Cash → Debt Balance → Interest。

在 Excel 中启用迭代计算：文件 → 选项 → 公式 → 启用迭代计算。将最大迭代次数设为 100，最大变化值设为 0.001。在假设标签页添加一个循环开关。

### 检查类别

**章节 1：币种一致性**
- 在假设标签页中识别并记录币种。
- 所有标签页使用一致的币种符号和金额单位。
- 单位行与模型币种一致。

**章节 2：资产负债表完整性**
- Assets = Liabilities + Equity（每个期间）。
- 公式：Assets - Liabilities - Equity（必须 = 0）。

**章节 3：现金流量表完整性**
- 现金与 BS 勾稽（CF Ending Cash = BS Cash）。
- 月度现金 vs 年度现金：Closing Cash (Monthly) = Closing Cash (Annual)。
- NI 与 IS 勾稽（CF 净利润 = IS 净利润）。
- D&A 勾稽到明细表。
- SBC 勾稽到 IS。
- ΔAR、ΔInventory、ΔAP 勾稽到 WC 明细表。
- CapEx 勾稽到 DA 明细表。

**章节 4：留存收益**
- RE 滚动检查：Prior RE + NI + SBC - Dividends = Ending RE。
- 展示组成部分拆分以便调试。

**章节 5：营运资本**
- AR、Inventory、AP 勾稽到 BS。
- DSO、DIO、DPO 合理性检查（若超出正常区间则标记）。

**章节 6：债务明细表**
- Total Debt 勾稽到 BS（Current + LT Debt）。
- 利息计算勾稽到 IS。

**章节 6b：股权融资**
- 股权发行所得勾稽到 BS 普通股/APIC 增加。
- 来自股权的现金增加 = 权益账户增加（必须平衡）。
- Equity Raise Tie-Out：ΔCommon Stock/APIC (BS) = Equity Issuance (CFF)（必须 = 0）。
- 第 0 年股权勾稽：第 0 年股权融资额 = 第 1 年期初股本。

**章节 6c：NOL 明细表**
- Beginning NOL（Year 1 / Formation）= 0（新业务从零 NOL 开始）。
- NOL 只在 EBT < 0 时增加（亏损必须实际发生才会产生 NOL）。
- DTA 勾稽到 BS（NOL 明细表 DTA = BS 递延所得税资产）。
- NOL 使用额 ≤ EBT 的 80%（2017 年后美国联邦限制）。
- NOL 余额非负（不得使用超过可用余额的 NOL）。
- 只在 EBT < 0 时产生 NOL。
- 应税收入 ≤ 0 时，所得税费用 = 0。

**章节 7：情景层级**
- 绝对指标：上行情景 > 基准情景 > 下行情景（NI、EBITDA、FCF）。
- 利润率：上行情景 > 基准情景 > 下行情景（GM%、EBITDA%、NI%）。
- 信用指标：杠杆指标满足上行情景 < 基准情景 < 下行情景（反向）。

**章节 8：公式完整性**
- COGS、S&M、G&A、R&D、SBC 由收入百分比驱动（无硬编码）。
- 预测年份公式一致。
- 无 #REF!、#DIV/0!、#VALUE! 错误。

**章节 9：信用指标阈值**
- 基于契约阈值将指标标记为绿色/黄色/红色。
- 汇总所有红色预警。

### 主检查公式

将所有章节状态汇总为一个主检查：
- 如果所有章节通过 → "✓ ALL CHECKS PASS"
- 如果任一章节失败 → "✗ 错误S DETECTED - REVIEW BELOW"

### 快速调试工作流

当 Master Status 显示错误时：
1. 滚动查找红色高亮章节。
2. 识别哪个检查类别失败。
3. 跳转到来源标签页调查。
4. 修复底层问题。
5. 返回 Checks 标签页验证是否解决。
